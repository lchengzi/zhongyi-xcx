# 中医食养筛选助手

这是一个原生微信小程序工程，产品边界是“非医疗食养教育”。它帮助用户检索、收藏和对照普通食品及官方食药物质，并把安全提示和资料来源放在推荐之前。

本项目不诊断疾病，不自动辨证，不开具处方，不生成剂量、疗程或自由配伍方案，也不替代医生、药师或营养专业人员。

## 页面闭环

2026-10-10，[用户界面升级](docs/product-interface.md)统一首页、收藏、对照、安全、详情与隐私的阅读样式，搜索和目录前置、长说明后置，增加本地原生导航图标。排版检查与微信手机预览分别记录，不把界面升级当作内容批准或正式上线。

- 食养目录：搜索、受控筛选、安全状态和解释结果
- 条目详情：规范身份、法规状态、传统食养资料、安全边界和来源
- 收藏：保存感兴趣的食材条目
- 对照：最多四项横向对照，不代表可以共同食用或配伍
- 安全清单：记录需要向专业人员确认的问题，不生成药方
- 本地数据与隐私：只显示数据类别和数量，并可一键删除收藏、对照及本次健康会话
- 官方完整方案目录：仅由用户主动选择已明确诊断的成人目标，显示发布门禁与审校进度
- 官方方案详情：只有来源、材料身份、整方安全及专业签审全部完成后，才整体显示原始材料、用量和做法

## 本地运行

第一次导入或准备手机试用，先看[微信首次编译与离线试用](docs/first-wechat-trial.md)：明确小程序导入目录、已有检查命令、离线任务及手机预览的确认边界。它不替代完整验收，未填写服务域名不阻止先检查离线功能。

1. 使用微信开发者工具导入本目录。
2. 当前 `project.config.json` 使用 `touristappid`；预览、上传和真机验收前必须由有权限的负责人替换为对应环境的真实 AppID，密钥不得进入仓库。
3. 整方审校底稿发生变化后，先运行 `npm run build:recipes` 生成不含待审材料、用量和步骤的公开索引。
4. 已登记版本的发布构建使用 `npm run build:release`；它会在生成公开索引前后校验目录、整方、公开索引和实际安全规则/展示代码等 12 件制品，以及当前 release、撤回清单和快照摘要。
5. 运行 `npm run check` 执行版本验证、结构、数据、分包、上传隔离和安全文案检查。
6. 运行 `npm test` 执行完整目录快照、安全规则、整方发布门禁、私有媒体隔离、隐私删除、本地存储异常、八页数据流和版本撤回/回滚变异测试。仅验收已有快照时运行 `npm run version:verify`、`npm run check`、`npm test`，无需先重建发布资料。
7. 按 `docs/p4-device-test-matrix.md` 在微信开发者工具及 iOS、Android、HarmonyOS 三端真机分别完成验收；没有实际设备与证据编号时不得标记通过。
8. P3 真人审校准备使用 `npm run build:professional-review` 重建摘要绑定的私有只读任务包；该命令只生成和校验 advisory 资料，不验证真人身份或签名，也不写入 `reviewed/published`。

只有在 18 条普通食品登记补齐直接身份、法规、食用形态/用途和安全来源、所有引用材料完成审校，且中医临床、药学、营养、合规与最终发布批准角色完成独立签审后，草稿才能转为可发布方案。方案必须按权威指南中的整体内容锁定来源、材料、原始用量与适用边界，不允许从收藏或对照项自动拼接。
