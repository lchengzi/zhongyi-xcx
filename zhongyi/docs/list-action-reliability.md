# 收藏 对照与安全清单操作可靠性

2026-10-09，收藏、对照和安全页补齐操作前的当前状态检查。复制咨询准备不再沿用旧画像和候选，已删除的 ID 不会被旧行事件重新加入，旧清空确认不会删除后来新选的条目。健康信息与清单仍只存在本次运行内，不新增联网或登录。

## 修复行为

| 场景 | 当前处理 |
| --- | --- |
| 打开页面后安全画像改变，再点收藏/对照 | 重新读取画像和评价；受限条目不能新加入，已有条目仍允许移除；红旗下停止候选操作 |
| 隐私删除后旧页面复制咨询准备 | 重新生成摘要，不复制已删除的用药状态、画像摘要或候选；已卸载页面直接拒绝复制 |
| 已移除收藏，再收到同一移除事件 | 当前行不存在时不操作；存储层使用只移除、不切换的接口，重复调用不会重新加入 |
| 隐私删除后收到旧行事件 | 只接受当前收藏/对照列表中仍存在的条目，不把旧事件当成新增请求 |
| 旧清单事件遇到新的画像、候选或隐私删除批次 | 刷新当前视图，不恢复旧勾选；重新显示后的新交互仍可使用，包括未选候选时的通用清单 |
| 清空确认期间删除隐私或改变对照 | 确认再次核对上下文；变化时提示重新确认，不清空新选择 |
| 清空确认期间页面隐藏、卸载或重复回调 | 旧操作失效；重新显示后需再次明确发起。重复点击只打开一个确认框，失败后可重试 |
| 本机记录此刻不可读 | 阻止写入、清单修改和咨询复制，保留读取失败提示；恢复读取不自动补做旧操作 |

收藏页、对照页和安全页在候选导航前也重读状态，失效行不能发起详情跳转；导航自身仍使用既有防重复保护。页面隐藏或卸载后，不执行迟到的上述写入、复制、清单或清空操作。

这些检查不自动清除红旗，不把未触发规则当作适合食用，也不改变 `.10` 的安全规则和历史内容。咨询准备仍不是诊断、处方、剂量或配伍建议。

## 关键实现

- [收藏页](../pages/favorites/favorites.js)、[对照页](../pages/compare/compare.js)、[安全页](../pages/plan/plan.js)：操作前刷新当前存储及画像；识别当前行；隐藏/卸载后拒绝副作用。
- [存储模块](../utils/storage.js)：新增 `tryRemoveFavorite`，基于一次读取只移除指定 ID；读取或保存失败时保留其他收藏，不先用可能失败的数组读取计算覆盖值。
- 对照与安全页的清空弹窗保存操作对象、隐私删除批次和当时对照 ID；安全页还绑定当前规范化画像。确认只能消费一次，不能用旧确认覆盖新状态。
- 安全页清单事件比较刷新前后上下文，复制则始终生成当前摘要。上下文只在页面内存使用，不发送、不持久化健康信息。

## 清空确认失败恢复
