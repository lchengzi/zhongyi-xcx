# 用户端目录搜索容错

2026-10-09，原生小程序目录支持连写、带声调和全角拼音，减少因输入形式不同而找不到已有条目的情况。改动只影响本地检索，不补写食材身份、拉丁名、别名或食用结论；当前目录仍是 2026-08-10 核对的 106 条历史快照。

## 可用输入与边界

| 输入示例 | 查找行为 |
| --- | --- |
| `黄芪`、`黄　芪` | 查找已有名称或既有字段，容忍中文中的空格 |
| `huang qi`、`huangqi`、`HUANGQI` | 对已有拼音字段作大小写与连写匹配 |
| `huáng qí`、组合声调、`huang-qi`、`huang’qi` | 将拼音声调和音节分隔转换为检索键，不改显示名称 |
| `ＨＵＡＮＧ　ＱＩ` | 支持 Unicode 兼容规范化的运行环境可按半角拼音查找 |
| `CORNUS   OFFICINALIS` | 拉丁名只容忍大小写和重复空格，不去除词边界或重音来推断等价名 |
| `黄芪 huang` | 不跨名称与拼音两个字段拼成不存在的整句 |

`ü` 在拼音键中保留为 `v`，接受 `u:` 写法，但不与普通 `u` 混同。没有登记的别名、拼音声调数字、错别字纠错和任意模糊匹配不在本次范围。百分号、下划线等仍作字面字符，不是通配符或正则表达式。

首页输入长度与既有过滤器统一为 60 个字符，保留用户输入的大小写与声调，规范化只在查询时发生。筛选、默认排序与姓名排序保持原规则，不将命中结果解释为适合个人食用。

## 页面适配与安全规则

[目录搜索适配器](../utils/catalog-search.js)先从现有公开目录筛出文字候选，再交给原有[版本化过滤器](../utils/filter.js)处理类别、来源状态、排序和硬性安全规则。适配器只清空已经应用的文字查询，不清除任何人群、红旗或过敏限制；结果始终是原安全过滤结果的子集。

[首页](../pages/index/index.js)与[输入绑定](../pages/index/index.wxml)使用新适配器，原防抖、操作前会话检查、隐私删除和后台回调保护保留。搜索不访问后台 API，不写收藏、对照或健康记录。Web 管理端与 API 的 SQL 检索本轮未修改，不声称已获得相同拼音容错。

运行环境缺少 `String.prototype.normalize` 时保留普通、连写及带声调拼音检索；全角及其他 Unicode 兼容字符不保证获得同等匹配。实际微信键盘组合输入、全角处理及基础库兼容性须按双端用例确认。

## 搜索清空与返回状态保护

2026-10-10，目录搜索补齐事件和延迟回调保护。搜索输入只接受当前页面版本的字符串，显示值与检索值均不超过60字符；输入期间不逐键更新页面版本，连续输入仍可使用同一有效输入框。键盘确认立即应用其值，不再等160毫秒；这只是原生页面函数与事件绑定验收，不证明手机输入法行为。

每次延迟搜索拥有独立令牌，清空、重新筛选、页面隐藏、卸载或交互上下文变化会取消并释放旧令牌。即使旧回调已进入队列，也不能重算结果或收回已展开列表。清空搜索及空态恢复按钮同时核对页面版本与当时的查询值，不让旧按钮清掉刚输入的新查询；只清筛选保留查询，全部清空仍不放宽安全规则。删除本地数据后，重复到达的旧输入或确认事件不能恢复查询；新显示的输入框仍可使用。

移除筛选标签只接受当前实际显示的键和值，异常键或旧控件不修改条件。查询不新增网络请求、持久存储或健康信息复制；版本化目录、过滤与安全制品不变。改动集中在[目录页面逻辑](../pages/index/index.js)、[目录模板](../pages/index/index.wxml)、[搜索专项](../tools/test-search.js)及调用真实页面的既有入口、演示测试。
