# 小程序本地存储可靠性

收藏与对照只在当前设备保存条目 ID。2026-10-08 的修复让页面根据实际存储操作结果反馈：保存失败不再提示已加入或已移除；读取失败不再把未知记录当作空列表修改；对照保存失败不提前丢失本次安全清单进度。健康问项和清单仍只存在当前运行内。

## 行为与实现

| 情况 | 用户看到的结果 | 状态处理 |
| --- | --- | --- |
| 收藏或对照写入异常 | 本机保存失败，请检查后重试 | 返回读取到的原 ID，不报告成功；不因失败清空清单 |
| 读取异常或存储格式不是数组 | 本机记录暂不可读，并提供重试按钮 | 阻止基于未知记录的修改；收藏、对照不显示误导性的首次使用空态 |
| 隐私页记录不可读 | 对应数量显示“未知” | 不把读取失败后的零计数作为删除完成的证据 |
| 安全页收藏或对照任一读取失败 | 保留重试入口，隐藏计数、候选、勾选列表及咨询准备 | 不显示伪造的零收藏、无排除项或部分咨询内容；原ID与会话勾选不变 |
| 收藏页或对照页任一记录依赖读取失败 | 隐藏卡片、对照入口、表格和修改控件，保留读取重试及红旗提示 | 不把失败依赖解释为未收藏/未对照；只清空显示数据，不删除原记录或勾选 |
| 首页或详情的收藏或对照读取失败 | 对应数量和标记显示“待读取”，停用该记录的修改按钮；目录、搜索、详情和出处仍可读 | 收藏与对照独立判断；另一项正常记录仍可操作，不改失败项的ID |
| 成功改变对照内容 | 页面反映新列表 | 清单重新待确认；保存相同对照不重置清单 |
| 重新整理失败 | 保留原清单进度，并提示失败 | 对照成功清空后才清空清单 |
| 读取恢复 | 点击重试后重新读取 ID | 提示消失，列表与计数恢复；不会自动补做之前失败的修改 |

[存储模块](../utils/storage.js)增加结构化结果 `ok / ids / changed / errorCode`，保留旧数组接口供兼容使用。目录、收藏、对照、详情和安全清单的修改入口均检查结果；移除单个对照项在一次读取结果上计算，避免先读取失败、再以空列表覆盖其他条目。隐私删除仍只处理本应用命名空间，不能验证删除时不报告全部完成。

读取失败时，安全页不复制缺少候选的咨询准备文字。错误提示不包含底层异常文本或健康明细，也不增加联网、登录或健康持久化。

## 首页与详情读取失败后的只读展示

2026-10-09，首页和食材详情不再把读取失败后的空数组当成“零收藏”“未收藏”或“未对照”。两个记录依赖分别维护可用状态：失败项的数量及条目标记设为未知，模板显示“待读取”，对应按钮停用；正常项仍可操作。卡片详情入口、离线目录、拼音搜索及详情出处保留，红旗和现有安全限制不放宽。卡片组件也拒绝不可用项的修改事件。

首页在记录可用状态变化时推进现有交互版本，失败或恢复前的旧卡片事件不能修改恢复后的记录。详情操作前重新读取当前状态。恢复不会自动重放旧操作，不清空原ID或内存清单；只有用户的新操作才可写入，成功改变对照时仍按原规则重置清单，收藏操作不重置。详情展示对象仍仅16个字段，可用状态单独保存，不新增健康持久化或网络请求。
