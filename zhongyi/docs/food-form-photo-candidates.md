## 明确缺口

1. 枸杞子：目录当前没有已发布的拉丁身份，具体身份与部位仍为 `pending`。通用 goji 干果图不能排除其他枸杞属来源；开放论文图片也缺少对应 voucher 或食材批次，因此不能借图片反向补齐身份。
2. 地黄：检索 6 条 GBIF 关联记录，其中 5 条完成视觉排除；另 1 条临时 JPEG 不完整，标记为 `retrieval_incomplete` 且不计入排除证据。仍未找到清楚呈现目录块根或食用加工形态的候选；整株或压制标本不降格替代。
3. 天冬：检索 4 条 GBIF 关联记录，其中 3 条完成视觉排除；另 1 条临时 JPEG 主图不完整，标记为 `retrieval_incomplete` 且不计入排除证据。已完成的画面只见枝、叶或果实，未找到可用块根视图；通用商品图不降格替代。

缺口、已检查来源和材料摘要已结构化写入 `content-private/media-candidates/food-forms/manifest.json`。任何目标食材必须恰好处于“有候选”或“明确缺口”之一，不能两者重叠或遗漏。

每条候选分别保存来源页精确标签、视觉观察、目录部位假设与物种证据类型，避免把来源原话和目录解释混写。Commons 候选保存页面 ID、文件标题、来源页、远端原图 URL 与远端 SHA-1；杜仲叶论文候选另存 DOI、PMCID、PMID、图号、完整作者、材料方法身份线索和远端 ETag。全部候选均保存字节数、尺寸、作者、权利人、许可证元数据、加工状态、基原覆盖和风险说明。来源、抓取链、画面语义和缺口证据各自做 SHA-256，并由候选 ID 对应的独立批准快照锁定；条目还绑定当前目录版本、规则版本和材料摘要。

本地麦冬文件保存的是派生预览，使用独立 SHA-256，不与远端原图 SHA-1 混用。缓存 JPEG 必须移除 APP1/EXIF/XMP 与 ICC 元数据；WebP 审校图必须是完整 RIFF/WEBP，尺寸不超过 1200 像素、字节数不超过 100 KiB，并拒绝 EXIF、XMP 和 ICCP 元数据块。

## 自动门禁

`npm run build:media-drafts` 离线重建本清单与画廊，不执行网络下载。`npm run check` 验证：

- 20 个目标的候选/缺口集合覆盖；
- 单基原与多基原的部分覆盖边界；
- 来源、许可、远端原图元数据和来源摘要；
- 候选 ID、食材 ID、完整来源摘要、抓取链、画面语义与本地文件摘要的独立批准快照；
- 本地路径、普通文件、MIME、尺寸、字节、SHA-256 和 WebP 元数据；
- 1 条本地副本与 18 条仅元数据状态的条件结构；
- 离线画廊无脚本、无远程 `src`/`href`，CSP 禁止网络连接；
- `content-private` 上传排除、0 个运行时引用、0 个二进制副本、0 个 release artifact。
- 私有根目录只允许清单、画廊及受管的 `source`/`review` 文件；拒绝遗留研究目录或任何未登记二进制。

`npm test` 还会变异发布资格、页面位置、路径、摘要、材料 ID、来源—基原绑定、权利/专业状态、远端/本地形态、跨食材交换、Commons 文件 URL、PMC 论文元数据与远端完整性标识、预览代理链、缺口证据、fallback 以及 WebP 元数据；任一漂移都必须失败。

## 晋升前仍需完成

当前 Commons 与 PMC 许可只作为待核元数据保存。即使来源声明 CC0、CC BY 或 CC BY-SA，也必须由权利审核人核对具体媒体对象、署名、改动标注、同方式共享和商业使用条件。身份/部位/加工形态仍需药材或生药鉴别人员与药师复核；多基原条目必须逐基原完成，不得用单图代表全部目录身份。论文实验流程也不得自动转写成官方食用方法。

完成真人签审后也不能直接复制到 `assets`。需要另建公开媒体清单和 fail-closed 构建器，把公开二进制加入版本制品与回滚快照，再设计卡片、详情、加载失败、无障碍和“不可用于鉴别”的邻近说明。
