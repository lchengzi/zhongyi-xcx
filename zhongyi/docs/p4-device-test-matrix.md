# P4 开发者工具与真机测试矩阵

## 1. 目标与放行原则

2026-10-09 起，验收范围为 iOS、Android、HarmonyOS 三端微信。兼容承诺只覆盖已记录并通过验收的系统与微信版本，不承诺所有旧版本。鸿蒙必须使用对应系统的微信实际验证，安卓结果不能代替。

本矩阵用于验证微信小程序主包/分包边界、冷启动与直链、tabBar 导航、安全状态跨包共享，以及开发者工具预览包与真实微信客户端的一致性。

- 自动检查通过不等于真机通过；没有实际设备、微信版本和证据编号的项目不得填写“通过”。
- 只使用虚构测试信息，不填写真实姓名、联系方式、疾病、过敏或用药信息。
- 任一红旗分流绕过、未发布整方材料泄露、tabBar 失效或直链白屏均为阻断发布的问题。
- 当前本机已由用户/工具配置非游客AppID，并完成工具授权；这不等于已取得预览或发布权限。其他电脑执行预览、真机调试或上传前，必须由有权限的负责人确认对应环境的AppID；不得把私钥或上传密钥放入仓库。

## 2. 分包基线

| 包 | 注册页面 | 加载策略 | 约束 |
| --- | --- | --- | --- |
| 主包 `__APP__` | 首页、收藏、对照、安全、隐私说明 | 启动加载 | 4 个 tabBar 页面必须留在主包；安全画像只存在当前进程内 |
| `subpackages/catalog` | 普通食材详情 | 首页 Wi-Fi 预下载；其他情况按需下载 | 可引用主包的食材与安全模块，不得同步引用其他分包 |
| `subpackages/official` | 官方方案目录、官方方案详情 | 首页 Wi-Fi 预下载；其他情况按需下载 | 必须是普通分包，以共享主包 `App.globalData` 中的本次安全状态 |

上传包中必须不存在：`data/recipes.js`、`tools/`、`docs/`、`.local/`、旧 `pages/detail/`、旧 `pages/official-plans/`、旧 `pages/official-plan-detail/`。运行时只允许引用脱敏生成物 `data/recipes-public.js`。

## 3. 执行前准备

1. 使用 Node.js 18 或更高版本，在项目根目录执行：

   ```text
   npm run preflight:device
   npm run version:verify
   npm run check
   npm test
   ```

   验收已登记的内容快照只做校验，不先重建资料。只有内容发布流程明确要求更新生成物时，才另行执行 `npm run build:release`，并记录对应发布版本。

   准备检查退出0只表示静态检查完成，不代表工具、AppID权限、服务或真机就绪。当前非游客AppID、空服务地址及工具检查范围见[准备记录](device-preflight.md)；离线功能与联网用例分开准备，不关闭域名校验。

2. 用稳定版微信开发者工具导入项目，确认项目根目录为本目录，基础库先选择固定基线 `3.7.6`，再用工具提供的当前稳定基础库重复关键用例。
3. 在“详情 / 代码依赖分析”或等价面板保存主包、两个分包的文件清单与大小截图。
4. 使用项目配置中的五个 `P4-*` 编译模式逐一编译。首次网络用例前清除编译缓存和小程序缓存；缓存态用例不得清除缓存。
5. 准备 iOS、Android、HarmonyOS 真机至少各一台。正式放行建议覆盖一台较低性能设备和一台当前主流设备。
6. 准备 Wi-Fi、蜂窝网络、断网三种状态。弱网可通过路由器限速或开发者工具网络模拟补充，但不能替代真机蜂窝测试。

同日[收藏和对照读取恢复](local-storage-reliability.md#收藏和对照读取失败后的显示与恢复)归入P4-20。P4-16三端正常流程另验；若自然出现依赖读取故障，检查卡片/表格及控件隐藏、重试恢复当前标记、差异模式保留且不自动移除或跳转。未发生故障的设备不登记该分支通过，也不破坏记录制造故障。

系统界面接口保护见[三端准备与异常处理](device-preflight.md#系统界面接口异常保护)。P4-35 只验证受控页面逻辑；P4-36 须三端分别记录实际布局与操作。异常保护不是放行失败底栏或错误系统标题的理由。

首页与详情的记录读取保护见[只读展示记录](local-storage-reliability.md#首页与详情读取失败后的只读展示)，自动项分别归入P4-22/P4-19。P4-16/P4-30 三端核对正常保存与显示；若自然发生失败，记录对应待读取标记、停用按钮、资料仍可读及恢复后的新操作。不可破坏真实记录制造故障，未发生的场景保持未验证，不用模板断言代替手机证据。

## 6. 记录与缺陷规则

2026-10-10的[收藏搜索清空保护](list-action-reliability.md#收藏搜索清空保护)纳入P4-27：三端分别快速切换查询并清空、从无匹配显示全部、清空后重新输入同一名称，再检查普通返回和隐私删除。确认新查询不会被旧点击清除、清空后旧查询不回流，收藏及对照未被搜索修改。自动102项仅为函数与模板检查；真实设备操作未执行时不登记通过，也不向设备注入伪造事件代替验收。

复制反馈和隐私边界见[主动复制记录](clipboard-reliability.md)。P4-33不替代P4-34，也不表示已发起的系统写入可被删除或取消。

- 每个“环境编号 × 用例”都应在 `p4-acceptance-record-template.md` 的副本中登记实际结果和证据编号。
- 状态只允许：`通过`、`失败`、`阻断`、`未执行`、`不适用（附理由）`。
- 修复后必须记录修复版本并重跑失败用例及 P4-01、P4-03、P4-04、P4-10、P4-15。
- 开发者工具通过但任一真机失败时，以真机结果为准。
