# 小程序公开目录与离线回退

## 范围

2026-10-08，配套平台增加唯一的匿名只读接口 `GET /api/v1/public/catalog`。它返回已经在小程序中展示的历史目录身份、来源及原有待审状态，不是新的内容发布接口；不返回配方底稿、用量、步骤、来源研究候选、后台备注、账号、审阅意见或编辑草稿。编辑质量通过不会改变这份目录。

小程序默认不联网，启动、搜索、筛选、收藏和安全问项均不会自动请求。首页“读取服务目录”仅在开发者配置内容服务后可用；请求固定完整目录，不带查询词、请求正文、账号凭据、收藏/对照 ID 或健康信息。搜索和安全判断仍在本地进行。

## 契约与校验

响应根字段仅有 `schemaVersion=1`、`purpose=historical_catalog_reference`、`releaseId`、`releaseDigest`、`contentVersion`、`sourceAsOf`、`items`。条目与来源的具体字段见 `utils/public-catalog-contract.js`，均按白名单构建。当前来源日期是 2026-08-10，不能称为截至今天的最新官方目录。

服务端从 SQL 读取已导入目录，检查版本元数据、行数、嵌套字段及全部数据摘要是否仍与启动时的已验证导入一致；数据库被绕过工作流修改时返回 503，不通过过滤字段掩盖污染。整个 `/api/v1/public/` 命名空间只准许一个固定 GET，不接受查询参数和写操作。其余内部 API 保留原有认证和权限控制。

客户端把响应的版本、字段、类型和每条资料与本地受版本管理的目录投影逐项比较，而不是相信服务端自报摘要或“已审核”状态。只有一致的历史资料才用于页面身份和来源展示；安全、人群、红旗和审校判断仍取本地制品。新内容版本需要单独验证与客户端版本交付，不是后台编辑之后直接推送。

## 配置与运行

1. 配套平台按 `../zhongyi-platform/README.md` 导入目录、构建和启动。无需登录即可检查 `http://127.0.0.1:4310/api/v1/public/catalog`；这只是本机 HTTP 验证，不是 HTTPS 部署。
2. `config/public-api.json` 只包含 `baseUrl`，默认空字符串。P4 完成真实 HTTPS 服务和微信请求域名配置后，再填入明确的 HTTPS 域名来源，例如 `https://你的实际服务域名`，不附路径或结尾斜线。不能把示例域名当作已部署地址。
3. 当前配置拒绝 HTTP、localhost/IP、用户名密码、路径、查询串、片段和无效端口；不降低 `project.config.json` 的 `urlCheck=true`。
4. 首页手动读取，可看到加载、成功、异常、重试和“使用本地资料”。6 秒平台超时之外还有独立截止处理，避免没有回调时无限等待。
5. 数据只在运行内缓存；切回本地或隐私页确认删除会取消读取并清空缓存。已取消请求的迟到回调不能恢复缓存；删除后的旧页面回调不会重新计算旧健康表单。
6. 读取期间离开并返回时，只接续已有请求；无待处理请求时不自动联网。成功、失败及独立截止均可更新当前页面，隐藏或卸载页面的旧令牌仍失效，详见[页面返回恢复](catalog-read-lifecycle.md)。

2026-10-11微信运行修复：运行代码读取`config/public-api.js`，与`config/public-api.json`逐字投影绑定；版本读取`data/version-runtime.js`中的releaseId/releaseDigest，与`data/version-active.json`绑定。修改配置或经正式流程激活版本后，执行 `npm run build:runtime` 再运行项目检查，不能只更新JSON后直接编译。生成器先验证正式制品和公开配置，再按事务更新两份JS；HTTPS校验与客户端复用同一函数，不执行旧投影文件，不接受额外密钥字段。`build:release`已接入生成器；内容回滚在同一事务中更新运行版本，不改变当前环境的服务地址。检查仍逐字拒绝不一致投影及运行代码require JSON。见[首次运行记录](wechat-simulator-first-run.md)和[对照与版本同步记录](wechat-compare-runtime.md)。

服务器和网络基础设施可能记录 IP、请求时间和标准访问日志；“不上传健康字段”不代表完全匿名。未来部署需明确访问日志的保留与清理政策。

## 工程验证与外部验收的区别

- `node tools/test-public-catalog.js`：配置、精确字段/版本校验、全部目录的本地安全结果不变、失败/超时回退、重复读取合并、取消与迟到回调、狭窄网络门禁。
- `node tools/test-catalog-read-lifecycle.js`：11项页面返回、已有请求观察、重复生命周期、隐私删除及红旗回归；传输和微信接口受控，不是设备证明。
- 配套平台 `npm.cmd test` 中 `tests/public-catalog.test.ts`：真实 SQL 和 HTTP、私有数据隔离、数据库异常拒绝、持久化重启，以及实际目录页/详情页/隐私页的运行逻辑。
- 跨工程测试只有 `wx` 网络传输由测试桥接；API 和数据库是真实的。不能将其描述为微信开发者工具、HTTPS、真实 AppID 或安卓/iOS 真机测试。
- 本次修改不改变现有 12 件受版本管理的内容/规则制品；页面运行代码已更新，旧内容 release 校验不证明新页面已经过真机验收。

正式部署、PostgreSQL、专业审校、可发布图片和双端验收仍需各自完成。
