原[对照模块](../utils/compare.js)把原始 `safety` 字段直接转换成文案。[修复前专项](../.local/compare-tests/baseline-20261009.json)中，用虚构条目把人群字段改为 `yes` 且移除来源，表格会显示“来源明确：适用”，而[详情格式化](../utils/format.js)为“待确认”。当前 106 条正式历史条目没有由此新增适用结论；这是一项故障注入发现的显示门禁遗漏，不声称已有真实用户受到影响。

五类人群现均调用既有版本化[安全引擎](../utils/safety.js)的 `populationRuleState`。缺少有效字段来源、来源已撤回或缺少独立专业意见时，不能靠原始肯定值或只翻转审校标记显示适用；来源支持的否定限制保留。没有修改安全引擎、正式内容、规则版本或受控制品摘要。

“本次筛选状态”只接受条目 ID 匹配的评估。缺失时显示“尚未评估”，不再按数组位置借用另一条目的结果；对象索引与评估内 ID 不一致也不采用。对照页原有红旗停止展示、操作前状态检查、最多四项及清空确认保护保留。

## 逐行阅读与横向表格

2026-10-09，对照页默认使用逐行阅读，按资料项目向下展开，每个单元带当前食材名称，无需左右滑动。横向表格仍可主动切换；两种视图使用同一组行、文字和差异标记，不重新解释人群、加工、来源或审校状态。文字单元另携食材ID与名称，随当前选择顺序生成，移除后重新绑定，避免把上一项名称与下一项文字混用。
