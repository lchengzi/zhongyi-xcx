# 微信首次编译与离线试用

这份指引用于把现有工程第一次打开到微信开发者工具，并安排小范围手机试用。它不是发布流程，也不替代[完整设备矩阵](p4-device-test-matrix.md)。当前仍是开发预览：106条目录属于2026年8月历史快照，专业审校待完成，没有公开实物照片或可发布整方。

## 先确认两项条件

需要本机微信开发者工具的安装位置，以及本人有开发权限的测试小程序AppID。只需确认路径、AppID和权限，不提供AppSecret、密码、上传私钥或登录凭据。尚未安装时先确认安装范围；登录由账号本人完成。

当前项目使用游客AppID，不能把它当作有权限的真机测试环境。本项目地址为`E:\xiaochengxu\zhongyi`；同级`zhongyi-platform`是后台服务，不是要导入的小程序目录。首次离线试用不用启动后台或数据库，也不用填写服务域名。

## 导入前检查

在小程序目录打开终端，依次运行已有命令：

```powershell
Set-Location -LiteralPath 'E:\xiaochengxu\zhongyi'
npm.cmd run preflight:device
npm.cmd run version:verify
npm.cmd run check
npm.cmd test
```

任一检查失败先保留错误，不继续生成预览。不要为了通过检查运行资料重建、回滚或修改版本摘要。准备检查退出0只表示静态检查完成；`readyForDeviceAcceptance: false`仍表示工具编译和设备验收未完成。

## 第一次编译

由有权限的负责人在微信开发者工具中导入上述小程序目录，配置对应测试AppID。保持域名校验启用，核对本地私有设置是否覆盖项目配置；不要把账号秘密写进项目。

先记录实际工具版本和基础库版本，以工程固定基线3.7.6作为一轮检查，再记录工具提供的当前稳定基础库。具体按钮位置随安装版本核对，不使用未经核实的命令行参数。首次先尝试项目中已有的`P4-首页冷启动`编译条件，确认能看到“非医疗 · 食养教育”和四个底部入口：食养、收藏、对照、安全。

如果出现项目路径、基础库或权限错误，记录错误文字、时间和所选条件；截图去除登录二维码、账号和凭据。不能用Node回归或后台浏览器截图替代实际编译成功证据。

## 离线试用任务

使用专用测试环境和虚构信息，不填写自己的健康情况。不需要登录用户账号，也不需要先填写安全问项。

1. 首页展开“使用指南与状态说明”。应能看到历史资料日期、待专业审校及实物照片未提供的说明；“本地目录可用”是当前正常模式，未配置服务时“读取服务目录”停用，不是故障。
2. 搜索“百合”，再试“baihe”。查看条目名称与命中说明，打开详情，核对目录记录部位、加工形态提示和来源。图片未提供不能当作真实图片加载成功。
3. 在详情点击“☆ 收藏”，回到底部“收藏”确认记录可见；再打开“莲子”资料。收藏只表示希望继续查阅，不表示适合食用。
4. 用“＋ 加入对照”选入这两项，再进入“对照”。检查逐行阅读、横向表格、仅看差异及返回；对照不能产生配方。若控件被安全状态停用，先记录原因，不通过清除真实风险或改规则来强行执行。
5. 进入“安全”，查看咨询准备及自记清单。未知保持未知，勾选不代表专业批准，不需要复制任何健康内容。
6. 查看“本地数据与隐私”。首次只检查说明；不要直接删除已有记录。完整删除用例仅在专用虚构测试记录上，经执行者再次确认后按设备矩阵执行。

首轮不测试整方材料、用量或做法。当前可查看待审原因和来源，不能为演示绕过发布门禁。

## 手机预览另行确认

编译后，先确认预览或真机调试将使用哪个测试AppID、哪些设备、是否生成并分发预览包，以及是否涉及上传。得到对应操作的明确同意后，再使用已安装工具实际支持的功能；本指引不授权自动上传、体验版分发或对外发布。

苹果、安卓、鸿蒙必须分别记录设备型号、系统、微信版本、基础库、网络、操作结果和证据。已有安卓与苹果手机可以先安排，缺少鸿蒙设备时保持未执行，不借用安卓结果。测试素材中不保留真实健康输入、登录二维码或其他账号信息。

## 保存首轮结果

将实际结果填写到[验收模板](p4-acceptance-record-template.md)的个人工作副本，保留原空白模板；仅填已执行的用例，其他项目仍为未执行。首轮任务只是发现导入、导航和基本体验问题，不覆盖弱网、分包下载、大字、隐私删除、红旗分流或完整三端兼容。

下一步按[完整设备矩阵](p4-device-test-matrix.md)逐项执行。联网目录还需手机可达的HTTPS测试服务、对应微信请求域名与明确环境；本机回环地址不能充作手机联网验收。专业审校、公网部署、预览与正式发布均分开批准和留证。
