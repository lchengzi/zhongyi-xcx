# 发布检查清单

每个可发布版本都应保留本清单的签字/工单记录。`npm run check` 通过只是必要条件，不代替人工医学、药学、合规和真机验收。

## A. 产品边界

- [ ] 首页、结果、详情、收藏、对照和安全清单均未提供诊断、辨证、处方、剂量、疗程或自由配伍。
- [ ] 搜索词、空状态、按钮、分享标题和错误提示均无疗效承诺。
- [ ] 对照页明确“并列展示不代表可以共同食用”。
- [ ] 安全清单是待咨询问题，不是药方或煎煮单。
- [ ] 传统食养资料与现代医学疗效结论有清楚区分。

## B. 数据与来源

- [ ] 每条数据的稳定 ID、规范名、物种/拉丁名、可食部位和法规身份已核对。
- [ ] 每条展示数据至少有一个可追溯来源，URL 使用 HTTPS，状态和复核日期有效。
- [ ] 食用限制、特殊人群结论只应用于来源明确覆盖的具体材料和部位。
- [ ] 安全人群字段使用 `yes/no/unknown` 显式状态；条件性慎用使用独立规则数组，没有把缺失值转成 `false` 或“安全”。
- [ ] 撤回、过期或待核实条目未进入普通筛选结果。
- [ ] 数据条数与当前版本的四批官方名称快照一致；若官方目录变化，已建立新版本而不是修改或绕过旧版 106 条断言。
- [ ] 本次数据版本、规则版本、变更摘要和审校记录可追溯。

## C. 安全流程

- [ ] 红旗症状入口、停止推荐逻辑和急救提示经过逐项测试。
- [ ] 儿童、孕哺、肝肾疾病、严重过敏、多药并用和术前等场景正确进入“需确认”或“阻止”。
- [ ] `unknown` 不会被当作允许，也不会获得安全排序加分。
- [ ] 硬限制不能被相关度、收藏或人工调整排序覆盖。
- [ ] 所有结果都能解释匹配理由、拦截原因、未知项和来源。
- [ ] 固定食养内容按完整方案审校，且不能由收藏项自动组合。

## D. 隐私与安全

- [ ] 默认仅持久化收藏和对照的必要 ID；会话清单与日志、埋点、分享参数不包含或留存症状、疾病、用药等健康信息。
- [ ] “本地数据与隐私”页只显示类别/数量、不回显健康明细；红旗分流期间仍可进入并执行删除。
- [ ] 一键删除已覆盖所有 `zhongyi_` 当前/旧版键、安全画像、红旗、过敏、疾病、用药、确诊确认和清单，并在成功后重置页面栈。
- [ ] 存储删除或验证失败时不会误报成功；重试可完成删除，删除后跨页返回、冷启动和旧键迁移均不会复活数据。
- [ ] 若启用云端能力，已完成个人信息影响评估、单独同意、最短保存期、删除和访问控制。
- [ ] 不请求与 P1 功能无关的手机号、位置、通讯录、相册或身份信息权限。
- [ ] 调试日志、源文件和测试数据不含真实用户健康信息或密钥。

## E. 工程验证

- [ ] `npm run check` 成功，输出实际条目数、页面数和检查结果。
- [ ] 已运行 `npm run build:release`；构建前后当前 release、12 件数据/规则/安全展示制品和快照均通过校验，公开索引与完整底稿同版本，所有未发布整方均不含材料、用量、步骤和食用方式，完整底稿仍在上传忽略清单中。
- [ ] `npm test` 成功，覆盖精确批次规则、三态、红旗七页阻断、敏感文本不落盘、隐私删除失败闭锁与删除后不复活、最多四项对照、陈旧 ID 清理，以及 AI 草稿与馆藏候选的私有隔离/篡改门禁。
- [ ] 微信开发者工具无编译错误、WXML 警告、网络域名或分包错误。
- [ ] 至少覆盖一台 iOS 和一台 Android 真机，检查小屏、字体放大、弱网和离线状态。
- [ ] 搜索、筛选、分页、详情、收藏、最多四项对照、安全清单、隐私摘要和一键删除操作已回归。
- [ ] 分享卡片、返回栈、冷启动、存储损坏恢复和空数据状态已验证。
- [ ] 主包体积和图片加载满足微信当前发布要求；正式 AppID、合法域名和隐私指引已配置。

## F. 人工批准与发布后

- [ ] 产品负责人确认功能未越界。
- [ ] 中医/医学审校角色确认传统资料和用户表述。
- [ ] 药学审校角色确认材料身份、相互作用与安全提示。
- [ ] 合规角色确认法规身份、宣传文案和隐私处理。
- [ ] 已准备数据或规则错误的快速下架、回滚和用户告知方案。
- [ ] 已安排官方目录、来源有效性和风险反馈的下一次复核日期。

## G. 官方完整方案门禁

- [ ] 方案主来源唯一，标题、章节、印刷页和 PDF 物理页均已人工核对。
- [ ] 所有材料（包括普通食品、调味料）均解析到统一身份记录和当前内容版本。
- [ ] 106 条官方食药物质目录与配方普通食品登记保持不同命名空间；跨登记碰撞、缺失或歧义均会阻断。
- [ ] 普通食品的配方出现证据与身份、法规、食用形态、安全直接来源完全分离；每条出现证据与配方材料行双向一一对应，公开包只保留已发布整方实际引用的记录。
- [ ] 所有材料的法规、部位、食用形态、过敏、疾病、相互作用和加工字段均已审校。
- [ ] 所有被当前声明引用的材料级来源仍为 `published`；人群 `yes/no` 均有直接字段级来源，正向 `yes` 不会在结构化专业审核前展示为适用。
- [ ] 每项被整方引用的材料均有中医、药学、合规三个独立审核记录，唯一记录 ID 绑定当前目录版本、规则版本与重算后的材料摘要；仅修改 `reviewed` 状态不能放行。
- [ ] 整方内容、中医临床、药学、营养、合规和最终发布审核均绑定当前来源摘要、整方摘要与内容版本，审核记录相互独立且未过复核日期。
- [ ] 删除、替换、重排、修改原始量或制作步骤会使整方摘要失效。
- [ ] 草稿、来源撤回、摘要漂移或任一审核过期时，材料、用量和做法完全不显示。
- [ ] 高血压、高脂血症等证型专属方案不会因症状文本或疾病标签自动出现。
- [ ] 分享、剪贴板、收藏和本地存储不包含已明确诊断目标或其他健康画像。

## H. 图片与生成内容门禁

- [ ] `content-private/media-drafts` 与 `content-private/media-candidates` 仍在微信上传忽略边界中；任何待审 AI 原图、提示词、馆藏候选、派生图、许可底稿或审核明细均未进入客户端包。
- [ ] 每张公开图片已明确区分 AI 语境插画、经核验真实参考照片和官方来源节选，没有把 AI 图标为实物图或鉴别图。
- [ ] AI 图片及其缩略、裁剪、分享和导出版本均保留显式与隐式标识，构建后验证通过。
- [ ] 图片邻近文案和无障碍标签明确“不可用于鉴别、采集、购买、食用、配伍、煎煮或用药判断”，图片不是安全状态或导航的唯一载体。
- [ ] 真实照片已绑定样本或食材批次；作者、权利人、许可证、来源和有效期可追溯。
- [ ] 图中基原变体、部位、加工形态和使用语境与当前材料字段及用途限制一致；多基原条目没有用一张图代表全部基原。
- [ ] 每个公开二进制及派生图的 SHA-256 已纳入 release/快照/回滚边界；替换字节、材料摘要或规则版本会使旧审核失效。
- [ ] 药材鉴别、药学、合规、权利和发布批准角色已使用独立记录绑定相同媒体摘要；没有由模型或开发者伪造审核。
