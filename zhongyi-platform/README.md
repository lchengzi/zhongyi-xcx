# 食养内容工作台

这是现有微信小程序的配套全栈工程。React + TypeScript 页面通过 Express API 查询关系型数据库（默认 SQLite，可显式选择 PostgreSQL），维护备注与私有来源、提交固定版本内容草稿，由独立账号完成编辑审阅，并记录资格核验、专业意见与来源查证。固定快照、独立批准、发布/撤回/回滚和冻结已接入后端 API 与 React 管理页面，公开教育能力默认关闭。它用于本机内容整理与工程演示；软件记录不等于真实资格认证，也不代表内容已经对外发布。新增页面和跨数据库验收结果见 [发布治理与验收](docs/publication-lifecycle.md)。

[初始化阶段诊断](docs/postgres-initialization-diagnostics.md)提供默认关闭的阶段、回滚与清理记录；不输出连接信息或原始报错，不自动重试，不代表历史自然故障根因已经修复。

## 启动

如需录屏、面试或安全复演，优先使用 [独立本地演示](docs/local-demo.md)：先`build`，再用`demo:prepare:compiled`准备专用库，按输出的`demo:start:compiled -- 实际演示ID`启动；不加载tsx，固定关闭外部AI和教育内容公开，不采用工作库配置。原源码CLI仍保留。`demo:verify`已验证源码CLI、编译正式服务、手动编译CLI三条真实React协作/重启链路，并另验编译准备与启动隔离。[全栈求职证据](docs/career-evidence.md)提供候选简历描述、招聘要求对应与面试实操清单，个人掌握程度须另行确认。下面的常规启动会使用配置的工作库，不要与演示命令混用。

新增[PostgreSQL运行/迁移账号隔离](docs/postgres-runtime-permissions.md)：显式授权、受限角色API、越权拒绝和授权回滚已有独立实测。生产启动强制自身连接只读权限检查；[容器凭据分离](docs/container-credential-separation.md)按命令限制秘密文件，并提供独立受限账号编排。原本机HTTP演示保持兼容，不能把新配置或编译入口测试写成Docker/生产部署已完成。

[容器备份与恢复](docs/container-backup-recovery.md)进一步分离备份密钥、可写导出和只读恢复挂载；本机编译入口已实测新库恢复、旧会话撤销及发布冻结。实际Docker挂载与卷恢复仍待验证。

[编辑记录读取与重试](docs/audit-read-recovery.md)区分加载、失败及成功空结果，隐藏旧记录和统计，保留未保存备注；重试只读，不因请求失败假报没有历史。

[发布管理读取与失败恢复](docs/publication-read-recovery.md)在加载或状态未确认时隐藏旧发布依据，保留未提交输入；列表失败不假报零条，已记录操作不会自动重发。

[协作审校读取与输入保护](docs/governance-read-recovery.md)分离账号、资格、审校和来源查询的错误与重试，失败不假报空结果，局部查询重试保留已选对象与未提交说明。

需要 Node.js 22.13+。在本目录执行：

```powershell
npm.cmd ci
npm.cmd run import:catalog
npm.cmd run build
npm.cmd run account:bootstrap -- your-admin-name
npm.cmd start
```

首次执行 `account:bootstrap` 会创建管理员并显示一次随机密码，请安全保存。用户名需为 3–40 位小写字母、数字或 `._-`，以字母开头；密码需为 12–128 字。也可通过临时环境变量 `BOOTSTRAP_PASSWORD` 指定密码，不要把密码作为命令行参数或提交到仓库。已有账号库会拒绝再次初始化，不覆盖旧账号。

打开 `http://127.0.0.1:4310`，使用该账号登录。数据库位于 `.local/editorial.sqlite`，刷新与服务重启均保留备注；账号会话最长 8 小时，刷新可恢复，退出会撤销服务器会话。密码和会话令牌不写入浏览器 localStorage/sessionStorage。修改权限或禁用账号会立即撤销该账号全部会话。

开发模式运行 `npm.cmd run dev`，打开 `http://127.0.0.1:5173`；Vite 将 `/api` 请求代理到端口 4310。生产构建由 Express 同源提供页面与 API。

`ingredients` 保存目录投影；`metadata` 保存来源版本和摘要；`editorial_notes` 以食材 ID 为主键关联目录；`audit_events` 保存备注操作、修订号、操作者和时间，不复制备注正文；`users` 保存账号与加盐密码散列；`sessions` 仅保存会话令牌摘要与账号外键；`login_attempts` 保存限流窗口；`security_events` 保存不含凭据的账号操作；`migrations` 记录数据库 schema 版本。

`source_records/source_versions` 保存来源当前头与不可变历史；`content_revisions/revision_sources` 保存草稿正文、固定版本引用与定位；`content_drafts` 保存当前修订及协作状态；`review_tasks` 绑定提交修订和摘要；`workflow_events` 留下来源/修订/审阅操作，不复制正文。新增内容不覆盖 `ingredients` 或原小程序 release。

`editorial_excerpts` 保存固定原文与初始许可；`excerpt_permissions` 追加当前许可的修订历史，不改原文摘要；`assistant_quota_days` 固定当日首次授权所用额度策略；`assistant_reservations` 保存固定引用、许可修订、调用摘要与数据库时钟授权；`assistant_events` 保存终态元数据，不复制提示词或模型输出。旧版本历史事件不补造新授权，已存授权不会通过重启归零。

`professional_qualifications` 以账号/资格修订为主键，保存内部依据编号、有效期、核验管理员和账号版本；`professional_reviews` 以食材/审校版本为主键，外键固定正文修订及资格修订。两表仅追加，撤销也追加新版本，不能修改或删除旧意见。

`source_checks` 以来源/核验版本为主键，外键固定来源修订，独立保存查证范围、信息域、期限、依据编号与核验账号版本。新核验不改 `source_versions` 或正文摘要；发布前检查在同一数据库读取事务内核对正文、专业意见和引用来源，结果不直接改变公开目录。

## 接口

默认账号模式：健康检查、就绪检查、登录配置、登录和限定的公开 GET 无需已有会话，其余接口均需 Cookie 会话；内部写请求还需可信 `Origin` 和 `X-CSRF-Token`。浏览器页面自动携带这些信息。编辑备注和待审资料不进入公开接口；独立教育 GET 默认关闭，只返回当前有效发布快照的白名单字段，不改变历史目录。

| 方法与路径 | 用途 |
| --- | --- |
| GET `/api/health` | 服务健康检查 |
| GET `/api/ready` | 匿名校验数据库公开投影/版本/摘要；无参数正文，成功 200、失败 503，不代表全部业务健康 |
| GET `/api/v1/public/catalog` | 历史目录身份与来源投影；拒绝所有查询参数和正文；数据库校验失败返回 503；不接受写操作 |
| GET `/api/v1/auth/config` | 登录模式，不返回密码或账号列表 |
| POST `/api/v1/auth/login` | `{username, password}`，返回账号、CSRF 令牌和到期时间；设置 HttpOnly Cookie |
| GET `/api/v1/auth/me` | 恢复当前账号会话 |
| POST `/api/v1/auth/logout` | 撤销会话并清除 Cookie |
| GET `/api/v1/users` | 管理员查看账号；不返回密码散列 |
| POST `/api/v1/users` | 管理员创建账号：`{username, password, role}` |
| PUT `/api/v1/users/:id` | 管理员更新：`{role, active, expectedRevision}`；撤销目标账号全部会话 |
| GET `/api/v1/security-events` | 管理员查看最近 50 条安全记录 |
| GET/POST `/api/v1/editorial/qualifications/:userId` | 本人/管理员读最近资格历史；仅管理员登记或撤销，要求 `expectedRevision` |
| GET/POST `/api/v1/editorial/professional/:id` | 读取私有固定内容与审校状态；对应资格人员记录通过/退回，原审校人或管理员撤销；要求正文、摘要、资格及协作版本 |
| GET `/api/v1/editorial/source-checks/:id/:revision` | 读取固定来源的私有核验历史及当前效力 |
| POST `/api/v1/editorial/source-checks/:id` | 独立管理员/审阅者追加核验或退回；原核验人/管理员撤销，要求 `expectedVersion` |
| GET `/api/v1/editorial/publication-preflight/:id` | 只读检查固定正文、专业意见与来源范围；不是发布批准 |
| GET `/api/v1/editorial/publications/:id` | 发布工作区，默认最近 20 条及当前有效快照 |
| GET `/api/v1/editorial/publications/:id/versions/:version` | 读取工作区并包含指定历史版本及其最新批准 |
| GET `/api/v1/editorial/publications/:id/snapshots/:snapshotId` | 固定快照与资格摘要，不含他人的私有资格依据 |
| POST `/api/v1/editorial/publications/:id/snapshots` | 管理员或编辑生成固定快照，不自动批准或发布 |
| POST `/api/v1/editorial/publications/:id/approvals` | 独立管理员批准或撤销，参与者不能自批 |
| POST `/api/v1/editorial/publications/:id/actions` | 管理员明确发布、撤回、回滚；重新检查全部依据 |
| GET/POST `/api/v1/editorial/publication-controls` | 管理员读取冻结历史或明确冻结/恢复，不自动复活旧发布 |
| GET `/api/v1/public/education/:id` | 默认关闭的固定教育内容 GET；不接受查询或正文 |
| GET `/api/v1/summary` | 版本、来源日期、条目/备注/事件数量 |
| GET `/api/v1/ingredients?q=&page=1&pageSize=12` | 搜索与分页；每页最多 50 条 |
| GET `/api/v1/ingredients/:id` | 资料和当前备注修订 |
| PUT `/api/v1/ingredients/:id/note` | `{text, expectedRevision}`；空字符串清空备注，最多 1200 字 |
| GET `/api/v1/events` | 最近 20 条编辑记录 |

错误：400 请求无效、401 未授权/会话失效、403 权限或请求来源校验失败、404 不存在、409 修订/账号冲突、413 请求过大、429 登录限流。来源链接仅用来打开已登记出处；服务不会抓取任意远端网址。

内部内容协作接口统一在 `/api/v1/editorial/` 下，必须使用正式账号；包括发布管理在内的内部内容协作请求上限 32 KiB，其余 API 为 8 KiB。来源/草稿契约见 [内容协作说明](docs/workflow.md)，发布路径、完整请求体、版本来源、公开字段和失败恢复见 [发布 API 契约](docs/publication-api.md)。

## 本地演示兼容与环境

默认 `AUTH_MODE=accounts`。若需要复现 P1 密钥模式，可在当前终端设置 `$env:AUTH_MODE = 'local-key'` 再启动；只在此模式生成或读取 `EDITOR_TOKEN`，账号模式不接受该密钥。密钥模式不能管理账号，刷新需重新输入密钥，不用于生产部署。

`PORT` 默认 4310，`DATABASE_PROVIDER` 默认 `sqlite`，此时 `DB_PATH` 默认 `.local/editorial.sqlite`；`ALLOWED_ORIGINS` 为逗号分隔的精确来源。选择 `DATABASE_PROVIDER=postgres` 还必须配置 `DATABASE_URL` 和已迁移的 `DATABASE_SCHEMA`，不自动迁移、创建目标或回退 SQLite。示例见 `.env.example`，应用不自动读 `.env`。默认仅监听本机 HTTP；生产必须显式 `TLS_MODE=direct`、账号/Secure Cookie、精确 HTTPS 来源与证书/密钥文件，反向代理信任未启用。仍需真实证书/域名、最小数据库权限、备份制度及上线验证，不能只设置环境变量就称生产完成。备份 CLI 另需 `BACKUP_ENCRYPTION_KEY`，服务不需要它。

`BIND_HOST` 默认 `127.0.0.1`；容器显式设为 `0.0.0.0` 时还需账号模式和明确可信来源。`db:init:postgres -- --schema NEW` 只用公开 seed 初始化全新目标，不读取工作 SQLite 或覆盖已有 schema。容器入口通过 `DATABASE_URL_FILE` 读取服务端连接秘密，不能同时传 `DATABASE_URL`；普通启动与既有操作者 CLI 继续使用原环境配置。
