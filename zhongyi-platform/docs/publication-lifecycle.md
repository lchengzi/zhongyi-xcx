# 固定版本发布内核与接入状态

发布内核把正文、独立编辑审阅、两类专业意见、资格和来源核验固定为一个不可变快照，再由未参与这些工作的管理员批准。发布、撤回与回滚只追加历史，不覆盖正文。四张治理表已接入增量迁移、只读迁移校验和业务备份恢复，应用 API、React 发布管理和默认关闭的公开教育接口已接入。共用发布 HTTP 已在真实 SQLite/PostgreSQL 分别验证，两种数据库的完整 26 项页面也分别有本机证据；编译入口的六项 HTTPS 流程另在两种数据库通过，见 [联合工程验收](https-runtime.md#postgresql-与-https-联合验收)。完整 PostgreSQL 迁移/恢复/运行套件已 48/48 通过、六次实际数据库重启并正常停止，见 [完整数据库终态](database-test-reliability.md#完整数据库最终结果)。数据库连接自身的 TLS、上线和真实专业签审仍待完成，不能称正式内容已经对外发布。

## 现有运行边界

当前 SQLite v8 或 PostgreSQL v6 共 28 张业务表，PostgreSQL 另有两张历史表，三个事件序列不变。现有匿名历史目录接口、小程序 `.10` 的 106 条历史目录、安全规则和素材公开状态没有改变；发布内核不改写旧目录，也没有对工作库执行迁移。

`publication-schema.ts` 定义快照、批准、发布事件和冻结历史四表，由 SQLite v8 与 PostgreSQL v6 的追加迁移创建。工程夹具使用真实迁移，不再手工安装 DDL。只读迁移支持 SQLite v3 至 v8，对应快照格式 v1 至 v6；旧文件仍按原来的表集合和摘要校验。不要在工作库手工安装 DDL，也不要直接调用仓储代替应用的鉴权接口。

`PublicationRepository` 和 `PostgresPublication` 实现同一契约的事务仓储，应用按数据库引擎构造对应仓储。管理 API 复用账号会话、Origin 与 CSRF；写入后仍在事务内重新核对权限和版本。React 管理按钮不会改变服务端开关，也没有启用工作内容公开。数据库仓储测试、HTTP 测试和页面操作须分别验收。

## 固定依据与独立批准

快照绑定当前通过编辑审阅的正文与全部固定来源，保存两名不同专业人员的意见、对应资格，以及每条引用的人工来源核验。固定资料必须覆盖身份、食用部位、加工形态、安全边界和目录适用范围；目录适用范围还需官方来源类别。条件来自当前有效记录，不是长期缓存的通过标记。

快照整理者、正文与来源编辑者、编辑审阅者、专业审校人和来源核验参与者不能自行批准发布。批准记录绑定快照摘要、批准版本、账号版本及发布冻结批次。资格或来源失效、账号变化、专业意见撤销、批准撤销，都能让已发布指针停止提供内容。新草稿不会替换旧快照，也不会把旧正文的审校意见移用到新正文。

人工核验字段是操作者的声明，不是系统认证。真实执业身份、资料语义和专业安全性仍需实际人员核验与签审；软件摘要与测试结果不能代替它们。

## 发布撤回与回滚

发布需要服务端明确启用 `EDUCATION_PUBLICATION_ENABLED=true`，默认及 CI 隔离环境均为关闭；只接受精确的 `true` 或 `false`，空值保持关闭，模糊值在开库前拒绝。启用能力只允许独立批准后的明确发布，不自动公开内容，也不支持本地编辑密钥模式。公开结果只包含教育字段、固定版本信息、出处与查证期限，不包含内部批注、资格依据编号、操作者信息或审校正文。公开字段仍须由人工核对，字段白名单本身不能证明教育说明的事实正确性。

撤回在能力关闭、冻结或依据失效时仍可移除当前发布指针。撤回后旧批准不能使内容复活；重新批准之后仍需明确发布。撤销批准再批准，也不会自动恢复旧指针。回滚只能指向曾发布的快照，且重新检查该快照对应的历史正文、当前专业意见、资格、来源、独立批准和冻结批次，不能绕过失效依据。

冻结更换批次，恢复沿用该冻结批次。恢复本身不复活旧批准或发布指针。PostgreSQL v6 备份恢复先校验全部原数据，再撤销旧会话并追加 `kind=recovery` 的新冻结批次，最后验证除这两类明确变更之外的全部数据、历史和序列一致。恢复到 v3/v4/v5 原结构时没有发布功能，不伪造冻结表或迁移历史；显式升级后空冻结历史仍保持未初始化的关闭状态。

SQLite v8 的迁移源若已有发布快照，导入 PostgreSQL 时先证明原始逐行摘要一致，再追加绑定该迁移编号及源摘要的冻结记录。原导入摘要与计数不改写。切换前 `--verify` 会单独核验这条新增冻结，再比较每个原始字段；后续业务操作改变数据后，不能继续拿原始基线当实时摘要。

## 完整性检查

校验分两层，任何一层失败都拒绝读取或写入相关发布记录。

1. 记录校验检查固定字段、嵌套结构和各自摘要。重算快照外层摘要不能掩盖伪造的子记录摘要、夹带字段、错误 JSON 或被改变的私有状态。
2. 关系校验将固定正文及其作者时间元数据、编辑任务、专业意见、历史资格和来源核验逐项与真实存储记录比较；检查发布指针所属食材、连续版本、批准引用、事件摘要链、冻结批次和撤回回滚转换。

完整性读取不使用页面最近 20 条历史。资格已经重发到第 23 版时，旧快照仍能追溯第 1 版资格，但第 23 版资格不能让固定第 1 版的旧授权重新生效。历史记录与当前可用性分开判断：过期、撤销或禁用不会使历史证据丢失，也不会被视为当前授权。

SHA-256 摘要不是人员数字签名，关系校验也不能抵抗有权限重写全部数据、DDL 和摘要的人。未来恢复流程还必须核对备份之后发生的撤销和人员权限，不能仅凭备份内历史判断当前可发布。

## 管理与公开 API

所有管理接口位于 `/api/v1/editorial`，要求有效账号，不接受查询参数，读取不接受正文。写操作使用严格输入结构、当前版本、明确确认和操作说明，不提供绕过专业或来源门槛的参数。

- `GET /publications/:id` 读取最近 20 条及当前有效快照的工作区；`GET /publications/:id/versions/:version` 额外包含指定旧版本和其最新批准，要求规范正整数；`GET /publications/:id/snapshots/:snapshotId` 读取指定固定快照。显示条数不限制服务端完整历史校验。
- `POST /publications/:id/snapshots` 允许管理员或编辑固定资料；审阅账号只读。
- `POST /publications/:id/approvals` 仅管理员批准或撤销批准；参与正文、审校、来源或快照整理的管理员仍不能自行批准。
- `POST /publications/:id/actions` 仅管理员明确发布、撤回或回滚。关闭能力时仍允许紧急撤回，不能发布或回滚。
- `GET/POST /publication-controls` 仅管理员读取冻结历史、冻结或明确恢复。恢复不复活旧指针。

管理响应的资格摘要只包含账号、版本、类别、状态、有效期和摘要，不包含他人的资格依据编号或核验备注；完整资格依据仍受原有管理员/本人权限限制。快照摘要指向服务端完整固定记录，不能对删减后的 HTTP 视图重算并声称验证了完整快照。

匿名 `GET /api/v1/public/education/:id` 是独立的限定字段接口，不修改历史 `/public/catalog`。只接受规范路径、精确 GET 和无查询/正文请求；默认关闭返回 503，没有当前有效指针返回 404。每次读取重新检查固定依据与当前授权，并验证公开目录和食材身份；目录或历史损坏返回无私有细节的 503。接口不接收用户搜索、健康问项、账号或图片上传，小程序尚未接入此新接口。

## React 发布管理与历史读取
