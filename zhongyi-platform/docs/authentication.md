管理员权限不代表中医师、药师或发布责任人身份。既有 106 条目录历史投影和待审状态保持原样，不能经由备注或角色调整自动晋级。健康会话、配方底稿和原生专业审核私有包未导入本服务。新增后台资格核验与固定意见独立保存，当前工程记录不代表真人审校，详见 [专业审校记录](professional-review.md)。

审阅角色现在可以作出编辑质量意见，但对备注、来源与草稿正文仍只读。服务端检查该条目完整内容修订历史和提交者，不允许参与过编辑的人自审，即使其拥有管理员权限。此次角色能力扩展不会写入任何专业审核状态；编辑通过内容仍保持 `private/pending/publicationEnabled=false`。详见 `workflow.md`。

## 数据与请求链路

```text
用户名/密码 → 可信 Origin 校验 → 数据库登录限流 → 异步 scrypt 验证
→ 随机会话 Cookie（HttpOnly / SameSite=Strict）
→ 服务器只存令牌 SHA-256 摘要、账号外键、到期时间和 CSRF 令牌

写请求 → 会话有效 → CSRF + 精确 Origin → 角色权限
→ expectedRevision → 数据库事务 → 内容与操作者事件 → 页面反馈
```

密码采用每账号独立的 32 字节随机盐，scrypt 参数 N=16384、r=8、p=1，64 字节输出；密码最短 12、最长 128 字。不存在公开注册、默认管理员或固定生产密码。首次管理员通过服务端 CLI 初始化，已有账号库拒绝再次初始化。

会话令牌 32 字节随机值，只出现在 HttpOnly Cookie；前端得到的 CSRF 令牌不是登录凭据，单独不能认证。绝对到期 8 小时，不自动续期。数据库查询每次检查账号启用状态；权限更新在同一事务内撤销全部目标会话。成功登录轮换当前浏览器已有会话；其他浏览器登录保持独立。默认本机 HTTP 不设 Secure，生产环境强制 Secure、HTTPS 来源和账号模式。

浏览器刷新先读取 `/auth/config`，账号模式再读 `/auth/me`；401 显示登录表单，网络错误保留重试入口。密码、Bearer 密钥、会话和 CSRF 令牌不写入 localStorage/sessionStorage。会话失效不会自动卸载工作台丢弃未保存备注；保存失败保留输入，退出需确认放弃，网络导致退出失败时不假装成功。尚未实现跨退出草稿恢复，可先复制未保存内容。

账号创建需异步计算密码散列，因此在真正提交事务前再次验证管理员会话，防止计算期间已被撤权却仍完成创建。不能禁用自己或撤销自己的管理员权限，数据库还保护至少一个启用管理员。权限更新带修订号，冲突返回 409，不覆盖他人更改。

账号页新增[未保存输入与请求中保护](account-edit-recovery.md)：离开或全局刷新需确认放弃，操作中禁止卸载；独立列表读取保留其他行输入，失败明确标注旧记录并暂停权限修改。未保存行绑定原修订，不因后台刷新自动接受新基准；并发409后可明确重新读取。仅页面内存保存输入，不增加密码持久化、自动提交或权限。

2026-10-11，账号管理的创建/权限更新回执和账号/安全事件列表接入严格纯TS运行时解析及未知写入核对，详见[响应边界](account-edit-recovery.md#严格响应与未知写入2026-10-11)。列表存在账号不证明创建归属或初始密码可用；未找到不证明原请求一定未提交。登录配置、会话、登录及退出回执随后接入 `shared/auth-response.ts`，验证范围见下节，不把客户端解析当成授权。服务器鉴权、限流、密码算法、会话撤销与数据库结构未因前端重构改变。

## 认证响应与未知结果（2026-10-11）

配置必须精确声明accounts/local-key，损坏配置不会进入备用登录模式。会话明确投影账号、64位小写十六进制CSRF值和有效到期时间，账号必须启用；凭据或未知嵌套字段被拒绝。客户端到期检查使用本机时钟，不替代服务器有效期判定。启动恢复只将HTTP401解释为当前无会话；网络或损坏成功响应保留错误/重试，不当作已退出，也不显示未核对身份。

登录回执核对规范化提交用户名。同步在途门禁防同帧重复提交，卸载取消等待；异常成功回执/超时/5xx保留输入并暂停，不自动重发。人工“核对登录状态”仅GET：完整有效且用户名匹配才进入工作台，不证明原密码或原请求归属；其他有效身份不接管。401或完整读到其他身份只描述当前观察，下一POST必须单独确认；无效或失败重读不解锁。普通输错密码的401仍允许改正，不把所有失败当作已创建会话。

退出必须收到精确 `{ok:true}` 或按既有协议明确401。未知回执保留工作台与未保存输入、禁用直接再退出，普通列表刷新不解锁。人工核对前再次说明：如果已无会话，将离开并放弃本页输入。GET401后才清除当前页面凭据；完整读到原同一账号/版本/CSRF/期限说明尚有会话，再退出需单独确认。其他身份或已轮换的会话不能悄悄替换支撑旧表单的凭据；失败核对保留输入与暂停状态。没有跨退出草稿恢复或退出回滚，浏览器取消请求也不能撤销服务器提交。

退出操作提示与概览读取错误分开：退出或其核对失败不冒充目录/审计读取失败，也不隐藏仍有效的读取结果。通用“重试”只对真实概览读取失败展示；退出未知结果仍通过专用核对按钮处理。后续实际概览请求若被服务器拒绝，则如实显示该批读取失败，不把缓存当作已验证的新状态。

复验：`node --import tsx --test tests/auth-response.test.ts`；构建后 `node node_modules/@playwright/test/cli.js test tests/browser/auth-response.spec.ts tests/browser/accounts.spec.ts tests/browser/accounts-recovery.spec.ts`。新增用例复用4314服务、专用测试账号，SQLite/PG夹具同步建同名身份；不清限流记录、伪造IP或修改产品限制。真实HTTP登录/退出之后仅损坏浏览器回执，单独GET核对会话；包含同帧登录、未提交登录、异身份观察、实际会话轮换和明确退出核对。原撤销权限/失败退出保留输入场景改为显式GET核对，未删除。证据见根 `.refactor/evidence/auth-response-20261011/RUNTIME.md`。

登录限流持久化到 SQLite：用户名最多 10 次/15 分钟，来源 IP 最多 50 次/15 分钟（含成功尝试）；单进程同时最多 4 次密码验证。来源 IP 取 Express 直接连接地址，不信任任意转发头。部署到反向代理前需配置可信代理和更完善的网关限流；当前限流是小规模本地实现，不宣称抗大规模攻击。过期限流记录在下一次尝试清理；过期会话在成功登录时清理。未知账号也执行密码计算，失败消息不区分不存在、密码错误与禁用。

SQLite的过期计数清理、IP与账号计数现在使用一个短事务，提交后再进行密码校验；成功会话仍单独提交。账号限流时仍提交IP尝试次数，实际写入/提交失败则回滚并拒绝登录，不跨异步密码计算持有写锁。限额、算法及持久性保持不变；测量与回归范围见[登录事务验证](sqlite-login-transactions.md)。

安全记录仅保留操作类型、操作者、目标账号和时间，不保留密码、Cookie、令牌或正文。登录失败统一记录为匿名，不保存提交的猜测账号。备注事件保存操作者用户名快照（用户名不可修改），不复制备注正文。

## 迁移与运行边界

schema v2 在 `BEGIN IMMEDIATE` 事务内增建 users/sessions/login_attempts/security_events，为旧备注事件增加 actor，旧值为 `legacy-local-key`。不改写旧备注、修订号或时间。迁移只执行一次，失败回滚；目录摘要不一致仍拒绝启动，不借迁移覆盖目录内容。

schema v3 增量添加私有来源版本、内容修订、引用关系及编辑审阅任务，沿用账号、会话和 CSRF 校验。旧账号/备注/事件不改写，不将专业签审引入普通角色模型。

默认本机 127.0.0.1，不自动暴露公网。生产模式安全配置失败即停止启动；不能把这个配置检查等同于生产部署验收。PostgreSQL、加密业务恢复、专业记录与发布批准现已有本机工程验证，具体边界见[数据库运行](postgres-runtime.md)、[业务恢复](backup-recovery.md)和[发布治理](publication-lifecycle.md)。真实专业资格与签审、公网部署、反向代理、密码修改/重置流程、MFA 和更完整的安全监控仍需落实；本机 HTTPS 通过不等于公网或数据库连接 TLS 通过。

设计参考：[Express 官方安全实践](https://expressjs.com/en/advanced/best-practice-security/)。测试证据见 `tests/auth.test.ts` 与 `tests/browser/accounts.spec.ts`，运行说明见项目 README。
