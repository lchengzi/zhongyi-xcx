# 协作审校页面读取与输入保护

协作记录、资格、专业审校、来源核验及发布前资料检查现在分别管理读取状态。失败不再表示没有历史，不在新关键词下保留旧选项；选项查询重试不重载已经打开的编辑器。正式内容、专业门槛、服务端权限、数据库结构和小程序安全规则不因本次界面修复改变。

## 查询与编辑分开

[useReadResult.ts](../web/useReadResult.ts)统一只读查询的加载、失败、取消和明确重试。每次读取先清除旧查询结果，各自保留错误与重试次数；返回、报错和结束回调均检查取消状态。它只调用GET，不重发写入；原有请求超时和请求编号处理仍由共用请求层负责。

[Workflow.tsx](../web/Workflow.tsx)只在成功读取时显示协作表格或空记录。[ProfessionalReview.tsx](../web/ProfessionalReview.tsx)分开处理账号列表、资格详情、待审食材和固定专业意见；管理员先确认账号列表，再读取所选账号的资格，账号列表失败不能被资格请求掩盖，也不能清除未保存核验说明。详情加载或读取失败时隐藏旧资格历史、正文依据和专业状态，保留且停用未提交输入；成功重读后才替换输入。

[SourceChecks.tsx](../web/SourceChecks.tsx)分开处理来源选择、核验范围食材、固定来源详情、发布检查食材及检查结果。局部选项重试保留来源核验输入和已经选择的范围；固定来源刷新失败时输入仍可见，但核验状态、旧历史与提交入口不能继续使用。选中的食材或来源有独立对象标识，改变搜索词不会悄悄改换编辑对象。再次点击同一个专业审校食材不会清空面板；发布前检查仍不执行发布。

这些界面保护不替代后端权限与修订检查，也不认证人员资格、来源事实或医学安全性。原有写入反馈和人工决定接口未增加自动重试、幂等键或新的发布权限。

2026-10-11补充：专业页账号、资格和意见已使用解码型只读查询及严格响应边界，不再仅凭泛型类型接收JSON。未知写入结果需明确完整重读后解锁；同账号失败刷新保留输入，确认切换账号则立即清理旧输入与历史，失败新账号读取不能继承旧说明。专业详情与本人资格必须同时核对成功，列表查询重试仍不影响已选对象。最新实现、证据及复验命令见[管理响应边界](workflow.md#管理端响应边界2026-10-11)及工作区根 `.refactor/evidence/professional-response-20261011/RUNTIME.md`；本页后续旧日期报告不自动升级为最新证据。

## 专业审校记录刷新与查询隔离

2026-10-10，固定版本的“刷新专业审校”只重读当前食材的审校记录与本人资格，不再同时刷新待审食材列表。列表的成功结果或失败提示均保持原状态，只有搜索词变化或主动点击“重试专业审校食材”才重新查询。两类读取仍各自显示加载状态；详情失败时列表保留，列表失败也不代表当前固定记录失效。

有未提交意见时，取消刷新或取消切换条目保留原意见和当前对象，不读取另一个专业记录。明确同意刷新后，等待期间保留且禁用输入，隐藏旧专业状态；失败保留文字，成功才重新加载输入。明确同意切换到另一食材则放弃旧输入，即使新条目读取失败也不能将旧意见带入新对象。列表仍可独立搜索，但详情读取中不能切换对象或作出审校决定。

九项协作读取浏览器用例包括新增的列表错误保留、取消操作和受控慢响应；原专业详情失败用例增加双向隔离断言。基于修正前生产页面的八项基线为7通过、1失败：失败点是刷新固定记录后多发一次列表GET，不是永久加载，也不是医学内容错误。[基线错误上下文](../.local/browser-tests/run-4cf8458d-d81d-4183-9c24-6d2950a59fac/governance-recovery-profes-ff929-put-without-prior-authority/error-context.md)与失败截图保留；后来新增的列表错误保留用例不计入这八项基线。
