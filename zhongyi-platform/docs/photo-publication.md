# 展示照片发布接口

本功能默认关闭，服务端与管理端“展示与发布”页签已完成本地链路验证；真实图片批准与公网微信接线尚未验收。没有新增真实公开照片。

## 配置与依赖

账号模式、既有私有原图库、已生成展示图目录及独立发布日志目录必须同时有效。服务不会自动创建这些目录，也不会自动发布已有候选。

- `PHOTO_DERIVATIVE_ROOT`：绝对路径，包含 `bundle.json` 与对应 JPEG；启动和读取时核验候选、尺寸、元数据规则及摘要。
- `PHOTO_PUBLICATION_ROOT`：已存在的独立私有目录；保存顺序发布/撤回 JSON，禁止与原图、展示图或 Web 静态目录重叠。
- `ENABLE_PHOTO_PUBLICATION=true`：显式允许照片发布/匿名读取；默认关闭。关闭时管理员仍可撤回。
- 复用已有发布控制：必须明确恢复发布才能发布图片；冻结或恢复代次变化后，旧图片不会自动复活，需要管理员重新发布。

路径必须为普通目录/文件，不接受符号链接或重定向目录。当前适用于单机受控文件系统；多实例共享文件系统、断电一致性及生产资源恢复尚未验收。

## 接口

| 接口 | 权限与行为 |
| --- | --- |
| `GET /api/v1/private-photo-derivatives/:candidateId`、`/:candidateId/image` | 账号只读核对展示版本及 JPEG；与公开图片隔离，同源、不接受查询或正文 |
| `GET /api/v1/editorial/photo-publications/:ingredientId` | 账号查阅最近 50 条发布记录；完整日志仍验证连续性与摘要链 |
| `POST /api/v1/editorial/photo-publications/:ingredientId` | 当前管理员会话、同源和 CSRF；发布/撤回，版本冲突不自动重试 |
| `GET /api/v1/public/photos/:ingredientId` | 匿名固定字段图集；核对内容目录、当前审核与资格、发布人、冻结代次及实际展示文件 |
| `GET /api/v1/public/photos/batch/:id1,:id2` | 最多12个互不重复的目录ID；固定回显请求顺序，只返回当前有效图集，撤回/失效项省略 |
| `GET /api/v1/public/photos/:ingredientId/:version/:sha256hex.jpg` | 仅返回当前有效版本中的 JPEG；旧版本或撤回不返回图片 |

公开请求只允许 GET，不接受查询参数或正文。所有响应 `Cache-Control: no-store`，小程序另有最长 60 秒会话内缓存；离线期间不承诺即时收到撤回。

目录与收藏页通过 `public-photo-batch.1` 分批读取已显示条目，每批最多12项、同时最多两个请求；加载更多保留仍有效的图片，只补读新增ID。缓存只在内存中，原期限不因重用延长；已验证的缺图也短暂缓存，网络/协议错误不自动循环重试。经过有效期限后，仍可见的页面重新核对；隐藏、断网、红旗或隐私清理取消请求并清除图片。单图详情继续使用 `public-photo-gallery.1`，二者均绑定历史目录发布版本。

卡片展示第一张图和简短署名/许可，完整来源与说明在详情查看；长署名不会遮住图片。图片失败回退到原有部位示意或资料图录，不改变历史部位状态与安全规则。当前真实公开来源仍关闭，真实照片待审；本地浏览器测试使用合成色块，不能计作真实食材上线或手机通过。

提交字段固定：`expectedVersion`、`action`（`publish`/`withdraw`）、`selections`、`displayReviewConfirmed`、`visualPrivacyConfirmed`、`reason`。发布选择 1–8 张，撤回选择为空。每个选择固定候选 ID、展示图摘要及送审/权利/专业版本。两个确认必须明确为 true；不允许客户端提供公开文案、作者、图片 URL、资格或审核决定。

公开文案来自固定送审版本；作者、固定来源修订、声明许可来自对应原件；修改说明来自展示图处理版本。复用已有权利人工核验和双专业当前资格，工程演练记录无法获得真实候选发布资格。最终展示/画面隐私确认不会替代这些审核。

返回的图集遵循小程序 `public-photo-gallery.1` 协议。私有路径、审核证据、账号及资格细节不会进入公开投影。没有图片返回 404，撤回或审核失效返回 410，停用/完整性问题返回 503。

## 存储与恢复边界

审核事实继续保存在 SQLite/PostgreSQL；图片与发布日志为单独文件资产。日志只追加、不覆盖历史，使用排他创建和文件同步；中断或损坏记录导致读取失败，不跳过损坏记录返回旧图。这些检查不是文件系统对抗性篡改的数字签名，也未证明异常断电后的持久性。

**现有数据库备份不包含原图、展示图和发布日志。** 独立加密文件工具及维护步骤见 [图片资源备份与恢复](./photo-resource-backup.md)。文件归档关联数据库备份摘要，但不包含 SQL，也不证明原子快照。恢复写入全新目录并保留隔离标记；历史响应的 `recoveryRequired` 为 true 时管理端禁用发布，明确读取后仍可撤回。核对数据及已撤回记录、建立新的冻结/恢复代次后，还须手动重发，旧图不会复活。不得把私有目录直接挂载到公开静态服务或 CDN。服务端和严格解析该新增字段的管理端应一起部署。

## 本地验证

`npm run test:photo-publication` 先构建当前界面，再使用独立 SQLite、合成色块 JPEG、独立账号及本机 Edge（Windows）/Chromium。测试内的人工核验字段只用于走通策略分支，不代表真人资格，不接触实际候选或工作库。测试资产保留在 `.local/photo-publication-tests/run-*`。

已验证 HTTP 发布/真实 JPEG/小程序严格协议、撤回与日志重开、权限/CSRF/异常字段、竞争只有一个成功者、审核版本变化、资格撤销、文件损坏、摘要修改、半写入记录、冻结恢复后不复活。实际 React 页面补验发布、坏回执重读核对、真实版本冲突及明确新操作、隐藏释放、图片不可读时仍可撤回、编辑只读、权利撤销。新增功能尚未由真实 PostgreSQL、微信联网或手机实际操作验证。

管理端在“图片审阅 → 选择候选 → 展示与发布”进入。展示图须实际解码且尺寸匹配；发布可保留其他已发布图片，或明确选择仅保留当前图。读取失败与未知写入结果保留输入、不自动重发。重新读取先核对历史；即使展示图损坏，管理员读取到发布记录后仍可撤回。隐藏、候选/会话切换会释放本页图片地址和取消读取。

## 待审材料

用户已确认暂时没有实际审核人员。`npm run photo:review-packet -- --asset-root ABS --manifest ABS --derivatives ABS` 整理私有资料：复制已核验展示图、保留来源/作者/声明许可/疑点/摘要，附中医师、药师及权利/画面核对的空白意见栏，不填姓名、资格或批准。原件及其附加元数据不装入资料包，工作库的审核记录也不读取或改变。输出在新的 `.local/photo-review-packets/run-*`，可打开 `index.html` 或打印；实际意见需按既有流程登记。
