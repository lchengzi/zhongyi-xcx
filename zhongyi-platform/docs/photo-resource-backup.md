# 图片资源备份与恢复

这是本地运维工具，不是公开 API。它补充数据库备份没有包含的原件、展示图及追加式发布日志。当前有隔离 SQLite、合成 JPEG、真实文件写入/读取及编译后 CLI 的本地验证；另有真实 PostgreSQL 加密SQL与文件配对恢复专项，旧会话失效、旧图集隔离及明确重发均通过。不同专项范围独立，不代表容器挂载、生产恢复、原子快照或异常断电验收。

## 范围与前提

- `originals`：精确原图清单字节和清单引用的 JPEG；不打包目录中的无关研究资料。
- `derivatives`：精确 `bundle.json` 和对应展示 JPEG。
- `journal`：全部连续、摘要可验证的发布/撤回记录；已有恢复限制也会保留。
- 加密使用独立 32 字节密钥、AES-256-GCM、随机 IV 和格式绑定。各文件另有长度及 SHA-256 校验。
- 归档保存关联数据库备份文件的 SHA-256，但**不包含、不解密、不恢复数据库，也不证明数据库和文件来自同一个原子快照**。

导出前必须停止相关服务和编辑/审批/资源写入，按数据库已有流程取得并验证备份，再导出图片。协作锁仅阻止使用本项目日志接口的并发追加，不能替代维护窗口、数据库事务或抵御外部文件修改。`--confirm-maintenance` 是操作者确认，不会自动停止服务。

三个资源根必须存在、普通且互不重叠，不接受符号链接/重定向目录；不得位于 Web 静态目录。归档和密钥均属私有资料。未审原件即使加密也不能进入公开包、CI 附件或聊天。

## 命令

在 `E:\xiaochengxu\zhongyi-platform` 运行。以下 `ABS_*` 都需替换为明确绝对路径，参数顺序固定。先设置且只设置一个密钥来源：`PHOTO_RESOURCE_BACKUP_KEY_FILE`（绝对路径普通文件，内容为标准 Base64 编码的随机 32 字节密钥），或 `PHOTO_RESOURCE_BACKUP_KEY`（同格式）。不提供固定演示密钥，不在命令行、仓库或日志中记录密钥。

```text
npm run photo:backup -- export --originals-root ABS_ORIGINALS --manifest ABS_MANIFEST --derivatives-root ABS_DERIVATIVES --journal-root ABS_JOURNAL --database-backup ABS_DB_ARCHIVE --output ABS_NEW_ENCRYPTED_ARCHIVE --confirm-maintenance
npm run photo:backup -- verify --input ABS_ENCRYPTED_ARCHIVE --database-backup ABS_DB_ARCHIVE
npm run photo:backup -- restore --input ABS_ENCRYPTED_ARCHIVE --database-backup ABS_DB_ARCHIVE --target-parent ABS_EXISTING_PRIVATE_PARENT --confirm-maintenance
```

生产构建后的宿主机等价入口是 `node build/tools/backup-photo-resources.js`，后接相同参数。独立容器入口与文件挂载配置见 [图片容器运维](container-photo-operations.md)；编译入口在宿主机已验证，Docker引擎尚不可用，不得据此声称Linux容器运维通过。

输出归档必须是新文件，已有文件拒绝覆盖。`verify` 只读认证、解析及关联摘要，不创建恢复目录；它不代替实际恢复、注册库核验或数据库验证。`restore` 仅在既有私有父目录下建立新的 `photo-recovery-UUID`，不覆盖源目录、切换服务配置或修改工作库。

## 恢复与重新发布

1. 保持服务停止、照片发布关闭，保全当前数据库、原件、展示图和撤回日志。按已有数据库流程恢复到新目标，核对会话撤销、权限与冻结状态。
2. 对匹配的数据库归档执行图片 `verify`，再 `restore`。实际恢复会重新打开原图库、展示图库和全部日志链。返回 `publicationEnabled:false`；恢复目录中的 `_recovery.json` 必须保留。
3. 离线核对数据库/文件版本、最近撤回、原图与展示摘要、当前账号资格、权利期限和审核版本。旧备份可能缺少后来的撤回，必须与保全记录对照，不能盲目恢复。
4. 经必要授权后，将服务配置指向新目录及对应数据库。旧图集仍受隔离限制；管理员页面显示恢复提示、禁用发布，读取成功时仍允许撤回。
5. 核对完成后，在现有发布控制中明确冻结、再恢复，创建晚于本次文件恢复时间且不属于归档旧代次的新控制。**该控制与教育内容共享，会使旧内容/图片发布指针失效，需统筹核对，不能仅为解锁一张照片随意操作。**
6. 重新读取当前材料，逐项手动发布。新控制本身不会使旧照片复活；权利/专业审核、当前资格与展示确认仍必须有效。实际公开配置和微信域名按授权另行启用。

旧代次在再次备份/恢复时继续禁止，不能通过重复恢复解除。损坏、非普通文件或悬空链接形式的恢复标记会拒绝读取，不当作“没有标记”。不要手动删除标记来绕过核对。

## 限额与故障处理

当前归档明文上限 160 MiB、加密封装上限 240 MiB、文件数上限 20000；单原件 8 MiB、展示图 512 KiB、原图清单 256 KiB、展示清单 512 KiB、单日志 64 KiB。关联数据库归档文件上限 48 MiB。超限必须显式评估新方案，不静默漏备份或提高生产限制。

错误密钥、认证标签、摘要、路径越界、未知日志文件、断裂日志或数据库关联不一致均失败。锁被占用时快速拒绝，不等待或删除他人锁；异常退出留下的锁须先核对进程与维护状态，再由操作者安排处理。程序只清理自身身份和随机标记都匹配的临时锁，不清理陌生锁。

文件写入采用排他创建和文件同步；未证明目录元数据的断电持久性。磁盘或后续图谱校验失败可能留下新的不完整私有恢复目录，原目录不变。不要把失败目录接入服务，也不要自动递归清理。密钥丢失无法恢复；密钥应独立托管。内存 Buffer 用后清零不是 JavaScript 字符串或系统内存的安全擦除保证。
