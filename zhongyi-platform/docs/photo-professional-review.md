# 图片专业审校

当前状态：严格协议、共享规则、SQLite/PostgreSQL事务、独立账号HTTP、类型客户端及React第四页签已接通。本机实际Edge页面11场景（Node12/12）、平台427/427、真实PG107/107及九组严格类型和生产构建通过；PG正常停止。图片权利审核、正文专业审校仍分别管理。工程测试不是现实资格认证或真人图片批准；公开照片仍0。证据见[工作台记录](../../.refactor/evidence/photo-professional-workbench-20261012/RUNTIME.md)。

## 固定对象和结论

`shared/photo-professional.ts`定义独立`private-photo-professional.1`，不改原图清单的pending标志。输入固定候选/原图来源绑定摘要、核对版本/摘要、送审版本/摘要、权利审核版本/摘要、专业意见期望版本及资格版本/摘要。客户端不能指定审核人、依据类别或公开标志；身份、部位、加工形态分别选择matches/uncertain/mismatch，填写依据定位、说明并明确确认。任何未知或不匹配不能批准，可登记退回。

规则由`server/photo-professional-policy.ts`共用，`photo-professional-data.ts`解析完整依据与资格历史，两种SQL适配在原生事务内调用，不复制判定。基础函数不写数据库，`PhotoProfessionalStore`已有双库实现。当前权利依据未就绪、失效或版本冲突不能审校。服务端再次核验权利审核人的有效账号/修订、有效期，而非仅信任传入的状态标签。

## 独立专业资格

复用原有professional_qualifications，以当前最新资格记录和具名账号为准。批准/退回需有效admin/reviewer会话及对应tcm_physician或pharmacist资格、明确核验确认、未过期且账号修订一致。所有历史图片核对、送审和权利审核贡献者均不能作该图片专业审校，管理员也不例外。

当前项目采用两个专业类别、两个不同账号分别记录的保守策略，不能由同一账号更换专业类别充当两方批准。不同账号本身不证明现实中的身份独立，真实资格和人员须另行核验。test-fixture只计工程记录；资格或权利依据任一为演练时，都不能进入真实专业就绪状态。

撤销只能指向当前固定依据下，该专业最近的一条批准；原审校人或当前管理员可执行，保留原资格用户/版本/摘要。资格被撤销后仍可撤销该旧专业意见，不要求重新取得资格。退回后必须修改并产生新送审版本，不能仅更新权利审核就重新批准原退回材料。

## 历史和有效性

服务端状态计算必须提供完整专业意见和贡献者历史（上限10000），不得用页面50条窗口替代。最近50条用于展示；两个专业各自的最新意见另行返回，可能位于显示窗口之外。连续版本、源头关系、具名账号、撤销前序和摘要必须有效，不能靠重新计算摘要把语义上不合法的记录变合法。

新记录摘要采用共享解析器的显式字段顺序，再对不含digest的规范对象做JSON/SHA-256；不是收到的JSON字节签名，不依赖调用方键插入顺序。后续浏览器须先严格解析，再按该规范字段顺序校验。尚无历史专业图片记录，因此不改任何既有记录摘要或旧迁移校验和。

状态含pending、changes_requested、recorded、eligible_for_derivative_review、revoked、stale。资格/账号/原图/来源/核对/送审/权利变化或到期，使旧批准失效而不删除历史。两方真实依据通过也只表示可继续脱敏衍生图审核；publicationEligible始终false，不是公开或医学/可食性批准。记录时间不能早于所依据的送审与权利记录。

## 账号API和严格客户端

`GET /api/v1/private-photo-professional/:id`供当前有效账号读取，`POST`仅允许admin/reviewer。候选由配置的私有库固定，不接受客户端上传身份或原图；拒绝查询参数、非JSON写入、额外字段、跨站请求和无效CSRF。原图路由仍只读。合法最大500字中文依据+1200字中文说明可放入8KiB请求上限；客户端不能指定审核人、资格依据类别或公开状态。

`shared/photo-professional-response.ts`严格核对固定回执、各专业最新意见、连续历史和所有依据。`web/photo-professional-api.ts`配对读取核对/送审/权利/专业四个版本头；规范字段顺序校验SHA-256，包括50条窗口之外的最近专业意见，拒绝回退和历史改写。读取取消会取消兄弟请求。写入先保存调用者的独立输入与会话快照，仅发送一次，不自动重试。

`npm run test:photo-professional:http`覆盖6项响应/客户端及5项实际SQLite HTTP；相同5项HTTP也已在真实PG107项中通过。包含双专业独立持久化、并发单胜、资格撤销、历史贡献者、合法最大中文输入及丢失回执后显式读取匹配。

## 专业审校页面

在“图片审阅”选择候选，再打开“专业审校”。页面显示固定送审与权利依据、本账号当前资格、两个专业的最近意见和不可变历史。编辑仅查阅；通过/退回需本人有效对应资格及贡献独立性，最终授权仍由服务端事务执行。身份/部位/加工分别选择，任一不确定不能通过，每次修改都会重置明确确认。撤销固定原专业意见及旧资格版本。

资格历史也按规范摘要、连续版本及不可变历史读取。任何读取异常保留表单并锁定，显式重读后才恢复；网络结果未知不假报失败未保存、不自动重发。即使拿到有效保存回执，后续读取失败仍保留输入，明确区分“已保存但未刷新”与“结果尚不确定”。核对到完全匹配的记录才清空该次输入；未找到匹配并不能排除延迟请求，新的手动提交另作确认。

`npm run test:photo-professional:browser`先完整构建，再以本机无头Edge操作真正React/HTTP/内存SQLite。11场景覆盖编辑只读、依据阻断、双专业/退回/撤销、无资格/管理员自审阻断、360px阅读和表单、未保存保护、坏回执、成功后刷新失败、真实版本冲突、隐藏及退出不确定、资格摘要篡改/撤销。原图、清单及公开目录不改，不证明真人审校、小程序实拍展示或真机。
