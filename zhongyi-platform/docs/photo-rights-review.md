# 图片独立权利审核

状态：数据层、账号HTTP/类型化客户端及React审核页签已接通，本地通过；新接口完整真实PG95项通过并正常停止。各轮证据见根`.refactor/evidence/photo-rights-20261012/RUNTIME.md`、`postgres-pool-shutdown-20261012/RUNTIME.md`、`photo-rights-http-20261012/RUNTIME.md`和`photo-rights-workbench-20261012/RUNTIME.md`。不是图片公开功能、专业签审或真实权利批准。

## 与现有流程的关系

私有原件清单 → 核对意见 → 不可变送审资料 → 独立权利审核 → 独立专业审校 → 脱敏衍生/公开批准与版本治理。

本模块落地“独立权利审核”的持久化基础、独立HTTP、严格JSON客户端及实际React操作。`private-photo-preview.1`仍只表达四类pending及publicationEligible=false，不原地改为approved。`private-photo-rights.1`与正文专业审校、正文发布批准分开；`PhotoRightsDetail.publicationEligible`恒为false。权利审核通过不能证明图片物种、实际部位、加工方式、可食性或医学正确性，也不能直接进入公开API/小程序包。

## 契约与权限

`PhotoRightsInput`严格固定当前原图/来源bindingDigest、送审版本/摘要、意见版本/摘要、审核expectedVersion；未知字段、批准/公开字段注入及缺失确认拒绝。批准、退回、撤销均记录依据类型、依据定位、署名方案、修改/衍生方案、有效期、说明及verificationConfirmed=true。服务端固定具名审核人、当时角色与账号修订、时间及独立SHA-256，不接受客户端传入审核人。

写入需当前有效账号会话及admin/reviewer角色。批准和退回必须独立于该候选所有历史核对及送审贡献者，管理员也不例外。撤销需当前版本的上一条为approve且指向同一送审摘要，只能由原审核人或管理员执行；不能把旧送审的批准撤销成新送审的批准/撤销。

批准有效期须在当前时间之后、不超过366天。这是项目要求定期复核的工程策略，不是法定许可期限。`manual-verification`表示具名人工登记的核对依据，不自动证明外部凭据真实；`test-fixture`只计recorded，不计rights_verified。测试中的人工分支同样明确标记ENGINEERING_SIMULATION_NOT_REAL，不能作为真实素材权利批准。

当前详情状态依次核对：最新原图/来源、最新意见及送审必须一致；最新权利结论须绑定该送审；批准人仍有效且角色/账号修订相同、未到期，才可显示rights_verified（人工依据）或recorded（工程夹具）。原图、来源、意见、送审、账号改变或期限届满都可使旧批准stale，历史保留。return/revoke分别为changes_requested/revoked，未有历史为pending。即使rights_verified，公开资格仍false。

## 数据库与恢复

SQLite追加v11，PostgreSQL追加v9；旧DDL/校验和不改。`photo_rights_reviews`20列，候选/版本主键、送审外键、具名账号外键，不包含图片字节。SQLite拒绝UPDATE/DELETE；PG另外拒绝TRUNCATE。运行角色仅有SELECT/INSERT，无覆盖/删除/清空权限。正式PG须先按既有拥有者流程显式升级，再核对新表最小权限；本轮不自动迁移工作库。

原生写事务内重验会话、三个版本头、贡献者独立性、有效期和insert；冲突409不写入。历史最多10000条，详情返回最近50条连续历史，读取有独立快照。SQLite与PG共用输入/规则/摘要/行解析，不复制审批逻辑。PG沿用既有全局业务事务锁，不引入重试或权限放宽。

快照格式9包括31张业务表，明确保留格式8的30表、格式7的29表等旧集合。备份业务验证不仅重算摘要，还核对连续版本、具名账号修订、送审/原图关系、批准期限、当时已存在的贡献者独立性和撤销前序。未来账号权限变化不能把历史抹去，当前有效性另算。恢复后旧会话照常失效、发布冻结照常保留；图片原件仍不在业务备份内。

## HTTP与客户端

`GET /api/v1/private-photo-rights/:id`使用有效账号读取详情与最近50条不可变历史；`POST`只允许admin/reviewer，写事务再检查当前会话、独立性与版本，成功返回201及具名固定记录。候选来自服务端私有注册表，不接受body内原图/审核人或公开字段。HEAD/PUT/DELETE、查询参数、跨站请求、GET带body及非JSON写入拒绝；写入沿用同源与CSRF校验。未配置图库返回404，本地密钥模式403，响应no-store和same-origin。原图仍只读，公开API未改变。

新路径单独16KiB JSON上限，容纳四项合法最大长度的中文权利文本；通用API原8KiB上限不变，超限仍413。字段上限、未知字段与批准确认等继续由严格输入解析及业务事务执行。

`shared/photo-rights-response.ts`校验详情、保存回执及显式重读：对象、连续版本、头摘要、具名账号/当时角色、原意图、状态/依据类型、批准期限和可见撤销前序；始终拒绝publicationEligible=true。旧记录不能被重读覆盖，允许合法50条滑动窗口。`web/photo-rights-api.ts`并行读取权利、送审和核对，核对同批版本及各层SHA-256，取消或失败中止其余读取。独立GET不是原子事务，不一致时拒绝本批；实际写入仍由后端事务重验。

输入、候选和会话在异步hash之前复制；同源Cookie/CSRF，不在URL放凭据、不跟随重定向、不自动重试写入。未知回执报不能确认，人工显式读取可通过matchesPhotoRightsAttempt核对当前保存记录；没有匹配不证明原请求绝不会完成。

## React工作台

账号工作台 → 图片审阅 → 选择候选 → 权利审核。编辑账号只能查阅，reviewer/admin可登记独立审核；参与该图片历史核对/送审的管理员也不能自审。界面窗口内贡献提示不是完整授权证明，服务端仍检查全部历史。撤销只对当前送审的上一条批准开放，并核对原审核人/管理员。

显示已读原图摘要、核对意见/定位、送审说明/部位/加工、三个当前版本及审核历史。依据类别和决定必须主动选择，不默认真实批准；工程演练明确标记、不计真实权利。日期按本机时区输入并转UTC，批准须未来366天内；署名、修改脱敏方案和审核意见均须填写，任何修改撤销确认勾选。历史最多显示最近50条，旧记录不覆盖。

未保存输入保护候选/页签/工作台导航，筛选隐藏候选不清空表单。保存失败或坏回执保留输入并暂停；显式重读匹配到固定意图才清空并确认，否则保留输入、再次提交须独立弹窗确认。读失败不能解除暂停。隐藏页面或未知退出取消读取/提交并保留输入；可见或账号核对成功不自动解锁，必须重新读取审核资料。不自动重发、不能靠清空输入撤销数据库记录或尚在处理的请求。

独立Edge实际十场景本地通过（Node11/11），覆盖审批/退回/撤销、过期拒绝、自审权限、360px只读历史、未保存保护、坏回执实际提交、意见冲突/新送审/额外确认、隐藏取消、异常读取及未知退出。原图库/送审/地黄追加三套回归25场景（Node28/28）通过；九组类型/生产构建、最终平台393/393和小程序边界11/11通过。这些隔离工程演练不替代真实PG终态、真人权利/专业审核或手机验收。
