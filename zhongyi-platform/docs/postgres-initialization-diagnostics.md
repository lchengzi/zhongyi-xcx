# PostgreSQL 初始化阶段诊断

`PG_INITIALIZATION_DIAGNOSTICS=true` 是独立、默认关闭的开关，仅由
`tools/init-postgres.ts`（含编译后的容器 `init` 入口）读取。启用后在 stderr
额外输出一条 `postgres_initialization` JSON；stdout 的初始化报告格式不变。
CI 子环境清除此主机开关，实际初始化专项按需显式启用。

记录受限阶段、相对耗时、固定错误码、回滚及 SQLite/连接池清理结果。
阶段包含参数、seed 读取/校验、临时 SQLite、快照、连接获取、事务开始、
事务设置、迁移锁、目标检查、建表、拷贝、校验、审计、提交及清理。
最多保留 32 个阶段时间点，超出仅计数；最初失败的阶段和错误码不会被
后续回滚或清理失败覆盖。未知错误码为 `other`，没有原始报错文本。

输出不含连接字符串、主机、数据库/角色/schema 名、路径、SQL、参数、
seed 或业务内容、密码、stack、cause。没有公开诊断接口；记录本身不是
业务批准、生产就绪或旧故障根因已修复的证据。只观察到 `postgres-copy`
等阶段不能单独判断网络、磁盘或某条 SQL 的原因。

关闭开关不会生成这条记录。直接调用 `initializePostgres` 或迁移库时，
必须显式传入 observer 才会采集；环境变量不隐式改变库调用。观察回调或
输出失败不改变业务结果，没有新增重试、扩大权限、降低证书校验或延长
连接/SQL/锁超时。

事务失败仍回滚一次并释放一次；回滚也失败时销毁该连接，保留最初异常。
初始化临时目录继续验证拥有权、链接、文件类型和精确文件清单；遇到
异常文件保留供检查，不递归清理。主操作已失败时，清理失败仅记录为
次级故障，不掩盖最初异常。提交响应失败不表示确定未写入，不能凭日志
盲重试初始化或覆盖已有 schema。

本地单元测试 `tests/initialization-diagnostics.test.ts` 使用最小结构化驱动
替身调用实际事务所有者，覆盖各阶段失败、回滚失败、无重试、只读隔离、
脱敏、操作编号隔离和观察者故障。它不替代真实 PostgreSQL：
`tests/postgres-deployment.test.ts` 检查编译入口默认关闭及重复目标拒绝
时的实际回滚/清理记录，`tests/postgres-permissions.test.ts` 检查非超级用户
初始化的成功记录。两者只在拥有权控制器的全新隔离数据库运行。
