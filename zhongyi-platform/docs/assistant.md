# 有来源的编辑辅助：提取、摘要、资料检查、修改建议与调用治理

## 交付与边界

管理端现在支持登记固定来源版本的原文摘录、SQL 字面检索、选取最多 6 条摘录、调用可替换的辅助器，以及核对后填入私有草稿输入。采用结果不自动保存；保存仍走原有修订、并发、权限和独立编辑审阅流程。摘录和新草稿始终 `private / pending`，没有内容发布入口。

首批交付身份、实际部位和加工形态的**逐字短句选取**；当前另提供相同事实范围的资料摘要草稿，不是开放式问答、食养建议或自动安全判断。引用必须是所选原文中的连续短句，不能改写、跨段拼接或使用未选来源；摘要段落则是模型改写，不能当作原文。真实检索/摘要质量仍需实际模型与人工评测，模型报告的缺口不能证明资料完整。

默认 `AI_PROVIDER=disabled`，原文登记和检索可用，但生成请求返回 503，不伪造答案。浏览器自动测试注入 `tests/assistant-fixture.ts` 的本地确定性模拟器；页面明确显示“非真实模型”，正式入口不导入它，环境变量也不能启用该模拟器。本批真实模型调用、外部资料传输均为 **0**。

## 响应可信边界与待核对写入

配置、额度及原文列表作为同一只读批次接入严格纯TS解析；核对食材、固定来源修订、私有/待核验投影、摘要格式、日期、条数及顺序。检索、会话或刷新代次改变立即隐藏旧批次并取消旧读取；其中任一读取失败不显示空列表、旧额度或“模型未配置”，也不能继续发送或采用。登记私有摘录不依赖模型启用。结构检查不证明原文真实性、使用权或专业批准。

摘录登记回执绑定当前食材、来源修订、规范化位置/原文、初始外发声明及录入者。初始 `allowExternal` 不可变；`externalPermission` 是追加修订的当前许可，撤回后两者可以不同。许可回执须保持原文身份与摘要，恰好推进一个修订，并匹配本次许可及操作者；固定重读拒绝不可变字段替换、修订回退或同一修订的许可替换。

网络中断、损坏成功回执或服务端5xx都可能无法确认写入结果。同步门禁阻止连点；保留输入，暂停相关登记/许可与生成/采用，普通检索或刷新不能解除。登记核对需显式确认：匹配记录存在且表单仍对应原输入时清空以避免重复；后来编辑的新输入保留，不把匹配当作原请求归属证明。最多50条的检索未找到时仅恢复编辑，新的POST必须另行确认，仍可能与迟到请求重复。许可核对使用固定摘录GET，有效当前记录只解除本地待核对状态，不归因先前PUT，再修改仍需确认。取消或损坏核对不解锁，不自动补发写入。

生成结果继续使用既有独立校验，并绑定本次选中的不可变摘录及许可修订。提取短句采用前再读取固定摘录、核对仍允许且修订未变；摘要建议保留原有草稿/来源/许可复核。读取只是当前观察，不是锁定整个人工确认期间的数据库事务；服务端授权、保存与后续专业批准仍独立执行。没有自动采用、保存、发布或真实模型调用。

## 本地使用

按 README 启动账号模式，使用编辑或管理员进入“内容协作 → 来源登记”，登记资料；再到“内容修订”关联固定版本，录入或保存私有草稿。

在“原文摘录与 AI 编辑辅助”展开登记表，选择关联来源的固定版本，填入位置和最多 1800 字原文。外部使用许可默认不勾选；保存只是 SQL 写入，不会调用模型。检索按文本/定位字面匹配，每次最多显示 50 条。

真实服务获准配置后，选取摘录并确认本次外部传输，才能请求整理。返回短句和位置后，逐条对照原文，勾选人工核对并确认替换教育说明；仍需另外点击“保存内容草稿”。取消采用不改变输入。保存失败保留输入，未保存摘录阻止提交审阅，重新加载须确认放弃输入。审阅者只能查阅摘录，不能登记、生成或采用。

## 资料摘要草稿

在“辅助任务”选择“有来源的资料摘要草稿”，切换任务会清空旧结果与发送确认，但不改变草稿输入。所选摘录、固定来源、当前许可和调用额度继续使用相同后端门禁；摘要和逐字提取共用每日次数，不另开不受控调用路径。

结果最多包含身份、实际食用部位、加工形态各一段（每段最多 240 字）。每段展示其关联的“资料 N”，下方同时列出所选原文连续短句（每条最多 160 字）、位置和来源版本。段落必须引用至少一条已核对的逐字短句，不能引用未选摘录、重复同类段落、增加批准字段、任意网址、个人档案或已知医疗/剂量字符串。未生成的类别由服务端补记缺口，安全边界始终保留缺口，不据此认定可以食用。

这些检查证明的是引用存在、逐字对应与格式受限，**不能证明摘要语义被原文蕴含**。例如所引原文写“根”，模型段落却写“叶”，仍可能通过结构门禁。固定离线样例故意保留此类可通过反例，报告不隐藏这一局限。提示词要求保留否定、条件、对象范围和资料分歧，但真实模型是否做到仍待评测；不能把 JSON Schema、正则或引用校验宣传为真实性保证。[官方文档也明确说明结构化输出仍可能有错误](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)

采用摘要改为先预览修改建议，再明确确认。采用只填入带类别标签的教育说明并补齐固定来源定位，不自动保存、不改食用部位/学名/安全字段、不提交审阅、不公开。原有来源版本冲突或合并定位超过限制时拒绝填入，由编辑先人工整理；保存仍是一个独立操作，生成失败保留已有草稿。

## 编辑确认的修改建议

这是基于已返回摘要的**本地确定性编辑方案**，不是另一次模型调用，也不是模型对整篇草稿作纠错、真实性评判或自动诊疗。当前草稿不进入外部模型请求。选取需要的身份/部位/加工段落，默认保留原文并追加，也可显式选择替换教育说明；预览列出采用前后全文、原文依据和采用后的固定来源定位。

仅所选段落对应的来源进入建议。原有引用保持，不自动删除可能不再适用的来源；编辑需人工整理。部位字段、拉丁名和安全边界保持原样。纯 TS 构建器限制说明 1600 字、固定来源 10 个、定位 400 字，并拒绝固定版本冲突；输入和原结果不会被构建器改写。

建议绑定食材、协作版本及全部当前编辑输入。输入变化后旧预览不能直接采用；即使恢复原输入，也不会恢复旧的人工确认。采用按钮有同步在途门禁，采用前读取最新服务端草稿和每条固定摘录的当前许可，检查版本、权限相关状态、原文、摘要指纹和许可修订。读取失败、并行保存、撤回再授权或组件离开均不写入编辑输入。缺失的固定来源版本读取完成后，再次核对本地上下文才更新表单。

这些读取是时间点检查，不是跨请求的原子锁；之后发生的服务端修改仍由手动保存的乐观锁和服务端权限门禁处理。许可控制外部发送及建议采用，不会追回已发送资料，也不会自动删除先前人工保存的内容。取消建议不改输入；采用不写库，只有“保存内容草稿”才生成私有修订，专业审校和发布继续独立。

新增只读接口 `GET /api/v1/editorial/assistant/ingredients/:id/excerpts/:excerptId`：须登录，只能读取对应食材的固定摘录和当前许可，不接受查询参数，不受列表 50 条限制，不调用模型、不消耗调用次数。提取/摘要/review 的生成响应在浏览器也经过运行时结构、引用关系和非发布标记检查；格式正确仍不代表语义正确。真实模型质量仍未验收。

## 资料缺口与来源分歧检查（review）

选择“资料缺口与来源分歧检查”，逐条选择已允许外部使用的摘录，并重新确认本次发送。此任务只判断选中资料的覆盖情况，不等于完整目录查证。输入额外绑定所选摘录的固定来源 ID/修订，不发送网址、会话或健康问项。

模型输出精确为 `{statements, findings}`：逐字短句沿用原门禁；findings 恰好覆盖身份、实际食用部位、加工形态各一次。每项 `{field, kind, text, evidenceIds}`，文字最多 240 字：

- `candidate`：有待核对的资料候选，至少关联一条逐字依据，不表示核验通过。
- `gap`：选中摘录缺少明确说明，允许没有引用，不强迫模型为缺失信息伪造出处。
- `conflict`：待核对的来源分歧，须关联至少两个不同 sourceId 的逐字依据。同一来源的不同摘录或修订不能充当两个独立来源。

额外字段、重复类别/引用、未知引用、孤立短句、无依据候选和已知越界/隐私字符串均拒绝。服务端由 gap/conflict 派生缺口，始终保留 `safety_boundary`，没有安全批准能力。无相关依据时返回三项 gap、空短句与引用，审计标为 `refused / insufficient_evidence`，已授权次数不返还。

界面并列展示项目、类别、原文依据和固定来源版本，没有“采用检查结果”的按钮；采用回调也拒绝 review，不能通过隐藏按钮以外的路径填入草稿。编辑应手动核实并修改资料，再走原有保存、审阅与发布流程。

检查同样受账号/CSRF、逐条许可、逐次同意、数据库额度、在途撤权、取消与终态审计约束。结构校验只证明关联存在，不能判断真实含义是否冲突；离线评测保留错误含义仍可通过的反例。输出 Schema 参照 [OpenAI Docs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)，未改模型选择、调用授权或密钥配置，也未进行真实模型调用。

## 外部许可撤回与持久化额度

摘录录入者或管理员可在摘录卡片上撤回/重新允许外部使用，审阅者和其他编辑不能修改。每次操作必须确认，并提交当前许可修订号；其他窗口已修改时返回 409，界面保留冲突提示并重读。许可操作不改写摘录原文、初始 `allowExternal` 或原摘要，而是在 SQL 中追加不可变历史；生成判断使用当前 `externalPermission.allowed` 与修订号。

许可管理不受内容草稿的提交锁限制，草稿提交后仍可撤回。撤回使后续调用不能取得该摘录的授权，也会使已授权任务的迟到结果无法交付；即使再授权，旧任务绑定的许可修订号仍失效。已经取得授权并发出的资料不能追回，取消请求也不能保证供应商停止处理或免除费用。许可撤回不是删除资料、来源权利证明或专业审核。

“辅助调用额度”从数据库读取，默认每个 UTC 日全库最多 20 次、每个账号最多 5 次；环境变量 `AI_DAILY_CALL_LIMIT` / `AI_ACTOR_DAILY_CALL_LIMIT` 可配置正整数，账号额度不得大于全库额度。服务不会自动读取 `.env`，零、负数、空字符串和非法配置拒绝启动。UTC 换日对应北京时间 08:00，不以客户端时钟计算。

调用前先在同一事务内重新验证会话、许可修订和计数，再写入固定授权记录。取得授权的失败、取消或输出被拒绝仍占用当日次数；发送前的缺资料、无许可或未配置服务等拒绝不消耗次数。刷新界面、重新登录、重建服务实例或正常重启数据库都不会清空当日额度。

数据库同时限制全库最多 2 个有效未终结任务、同账号最多 1 个；授权有效期固定为 45 秒，结束状态提交后释放并发占位，进程失联则等待到期。过期后不交付旧结果，当日次数不返还。计数和有效期使用数据库时钟，跨连接池由事务锁协调；前端按钮和进程内限流只是辅助，不能替代数据库门禁。

当日首次取得调用授权时固定该日额度策略；同库不同实例配置不一致返回 409 `assistant_policy_conflict`，不能通过重启或调高配置绕过已用次数。统一配置后重试，或等待新 UTC 日采用新策略；不删除账本重置。用完次数返回 429 `assistant_quota_exceeded`，并发占位满返回 429 `assistant_busy`。

这是一套**调用次数**上限，不是金额预算或供应商账单保护，也不保证客户端超时后外部服务器没有任务继续运行。真实开放前仍须确认供应商项目的费用约束、密钥权限、留存政策及真实评测。数据库额度按同一业务库生效，不覆盖其他独立数据库或直接使用供应商密钥的请求。

## 服务端接入准备，不代表已开通

当前真实适配器使用固定 HTTPS Responses 端点，不接受客户端模型、URL、提示词或密钥。需要先确认供应商、账号访问、支持结构化输出的明确模型、费用授权与摘录使用权；密钥通过服务端环境/密钥管理配置，不放前端或聊天中。本地应用不自动读取 `.env`。

- 默认：`AI_PROVIDER=disabled`。启用须同时指定 `AI_PROVIDER=openai`、`AI_EXTERNAL_ENABLED=true`、`OPENAI_API_KEY` 和 `AI_MODEL`；缺项拒绝启动，没有默认模型。
- 请求为 `text.format` 严格 JSON Schema，禁用工具、流式和后台执行，设置 `store:false`；逐字提取最大输出 1800 token，摘要和资料检查最大 2600 token，三种任务分别使用封闭对象 schema、全部必需字段和所选摘录枚举。应用另行验证字段、唯一引用、逐字匹配和非医疗范围。拒绝、未完成、畸形/过大响应不会成为草稿。[官方结构化输出说明](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)
- `store:false` 不能被宣传为零留存。供应商的滥用监控、账户数据控制及适用限制需另行确认。[官方数据控制说明](https://developers.openai.com/api/docs/guides/your-data)
- 仅发送目录食材名称、所选摘录 ID、固定来源标题、原文位置和正文；资料检查还绑定固定来源 ID/修订，不发送账号、会话、备注、健康问项或原始网址。标题和定位也接受发送前的范围与个人信息筛查。
- 每条摘录须有当前有效的外部使用许可，另需本次确认；许可修订在数据库授权和结果终态提交时再次核对。此声明不是来源权利证明、身份核验或专业批准。
- HTTP 调用截止 30 秒，响应最大 64 KiB，无自动付费重试；进程内与数据库同时提供并发门禁，数据库授权规则见上文。调用前后重查账号/会话，撤权、许可变化、取消或授权到期不交付迟到结果。
- 耗时记录为本次服务处理时间；token 数仅信任安全范围内的整数。未配置价格时费用为未知，不记免费。配置经核对的输入/输出每百万 token 价格后才生成估计，不是账单，未分别计算缓存等价格差异。

持久化次数、逐条许可撤回及限定事实范围的摘要已实现；尚缺供应商金额约束的实际配置、数据留存生命周期和真实模型质量/时延/成本实测。必须确认这些条件后再评估正式开放；不能只填密钥就认定 P3 或生产部署完成。更广的资料任务、自动检索相关性和用户端问答不是本批已交付能力。

范围和个人信息正则只是有限防护，不是完整分类器。摘录必须人工核实出处、文字、权利和身份，不输入个人档案。真实质量评测应覆盖不同资料形态、无依据答案、越界请求和更复杂的注入样例。

## 数据与接口

历史调用治理增量为 SQLite v5 / PostgreSQL v3：在 SQLite v4 / PostgreSQL v2 的 `editorial_excerpts` / `assistant_events` 基础上新增 `excerpt_permissions`、`assistant_quota_days`、`assistant_reservations`，当时共 21 张业务表；工程当前版本见下方生成契约说明。历史更新/删除受触发器禁止，PostgreSQL 还禁止 TRUNCATE。摘录摘要绑定食材、固定来源版本、位置、正文和录入许可；修订来源和撤回许可不会改写旧摘录。数据库超级用户/DDL 权限不在防篡改保证内。

只读迁移支持 SQLite v3/v4/v5 的 16/18/21 表，分别保留快照格式和原摘要。旧 PostgreSQL v1/v2 须备份、停写后显式 `--upgrade`，不自动加表。旧版本的调用没有新授权记录，不伪造历史次数或追溯补扣；新额度从升级后的首次授权起记录。已有 v5/v3 授权则随迁移、服务及数据库重启保留。

调用记录仅保留操作者、提供方/模型、状态、摘要、通用错误码、耗时/token/估计成本，不存提示词、输出正文或凭据。管理员可查最近 50 条。权限撤销后的终态仍留痕；审计写入失败不向客户端交付成功结果。

授权记录另存固定摘录 ID、摘要、许可修订及数据库时间，不复制原文；许可历史存操作者、状态、修订和摘要。终态完成表示结果已通过服务端核验与审计，不是客户端实际收到的回执。审计失败或进程崩溃可能留下待过期占位，仍不会返还已取得授权的次数。

接口根路径 `/api/v1/editorial/assistant`，正式 Cookie 会话必需；写操作还需 Origin 与 CSRF，拒绝本地密钥兼容模式。

| 接口 | 契约 |
| --- | --- |
| GET `/config` | 提供方/模型/是否模拟与启用状态、scope；`editorial_extracts_and_summary` 支持摘要，`editorial_extracts_summary_and_review` 同时支持资料检查，不返回凭据 |
| GET `/quota` | 当前 UTC 日、固定策略、全库/当前账号的次数与有效占位、配置是否一致；不返回其他账号明细 |
| GET `/ingredients/:id/excerpts?q=` | 字面检索，最多 50 条，仅允许 q 参数 |
| POST `/ingredients/:id/excerpts` | `{sourceId, sourceRevision, locator, text, allowExternal}`；编辑/管理员 |
| PUT `/excerpts/:id/permission` | `{allowExternal, expectedRevision}`；布尔值与非负整数修订；仅录入者或管理员，追加历史 |
| POST `/ingredients/:id/generate` | `{evidenceIds, confirmExternalTransfer, mode?}`；mode 为 `extract`、`summary` 或 `review`，缺省保持逐字提取；最多 6 个唯一 UUID；编辑/管理员 |
| GET `/events` | 最近 50 条终态元数据；仅管理员 |

正文不接受自由医疗问题、客户端提示词、发布或审校字段。生成从不直接修改 `content_drafts`，也不进入匿名公开目录。

生成响应携带 `mode` 与 `sections`；提取和检查时 `sections=[]`，检查额外携带 `findings`。模型摘要输出必须精确含 `{statements, gaps, sections}`，每段为 `{field, text, evidenceIds}`；服务端派生缺口并附原有 `citations`、元数据与私有待审状态。模式参与请求摘要绑定，不接受客户端配置模型。资料检查不增加 SQL schema；工程当前为 SQLite v8 / PostgreSQL v6（包含后续来源核对和发布增量），调用正文仍不存入审计。
