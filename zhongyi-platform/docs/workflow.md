# 来源 内容修订与编辑审阅

## 产品边界

该流程用于内部资料整理质量，不是中医师/药师专业签审。新增来源和所有内容草稿始终私有、待专业审校、未发布。来源登记没有自动抓取或核验网页，也不代表内容或图片获得使用授权。已有 106 条历史目录投影、小程序 `.10` release、规则和备注均不被新草稿覆盖。

后台角色本身不授予专业资格；独立管理员发布批准属于另一层权限，没有公开草稿、发布配方、疾病诊断或自动剂量 API。本模块不接收用户健康会话。可选 AI 编辑辅助另见 [辅助流程](assistant.md)，真实外部调用默认关闭。[资格核验与专业意见](professional-review.md) 与 [固定快照发布](publication-lifecycle.md) 是独立层，不把编辑质量意见当成专业批准或公开授权；草稿对象始终私有，公开仅可能来自满足全部门禁的独立固定快照。

## 状态机与并发

原文摘录及外发许可同样采用严格回执、同步门禁和未知结果人工读取核对；普通刷新不恢复写入权限。摘录初始外发声明与当前追加许可分开，不能把撤回许可当作改写原文。详见[辅助响应边界](assistant.md#响应可信边界与待核对写入)。

```text
保存新内容修订 → draft → 提交（锁定该修订）→ submitted
                                               ├─ 独立审阅退回 → changes_requested
                                               │                 └─ 保存新修订 → draft
                                               └─ 编辑质量通过 → editorial_accepted（私有/待专业审校/未发布）
                                                                 └─ 保存新修订 → draft
```

`revision` 是不可变正文修订号，保存新内容才递增；`lockVersion` 是协作版本，保存、提交、审阅决定均递增。写请求必须携带对应版本，否则返回 409，不覆盖新数据。已提交草稿不能改写；退回或编辑质量通过后必须保存新修订才可重新提交。任务绑定提交时的正文版本及 SHA-256 摘要，唯一索引保证每个条目最多一个待处理任务。

草稿作者和管理员可修订/提交；编辑不能修改别人的草稿。管理员和审阅角色可作出独立审阅意见，但提交者以及在完整修订历史中参与过该条目编辑的人均不能自审。审阅意见必填，无意见不能通过或退回。任务处理并发返回一成功一冲突，不能重复审批。

界面只展示最近 20 个修订，但参与者集合来自完整历史，不能用分页隐藏自己的早期编辑记录来获得审阅权限。协作写入事务会重新检查账号启用、角色和账号修订，旧角色信息不能继续写入。

SHA-256 输入包含基础 release、食材 ID、草稿内容和引用的固定来源版本。提交和决定时重新计算摘要并校验引用对应关系，发现来源快照或内容损坏时拒绝流转。摘要用于版本完整性，不是真人签名或专业背书。

## 数据模型

2026-10-10，编辑审阅页与专业审校页统一使用[固定来源审阅卡片](professional-review.md#固定来源审阅卡片)。出处按来源编号及修订号与原文定位对应，不依赖响应排序；补齐登记机构、记录人及录入时间，并明确录入不等于发表、登记不等于核验。无法唯一匹配时不显示替代链接，也不能记录通过；原权限者仍能退回说明问题。后端固定版本、摘要、独立性、冲突及发布门禁不变，未改API或数据库模型。

来源登记的 `verificationState=pending` 保持原有固定版本契约；来源查证另存不可变 `source_checks`，不改已绑定的正文摘要。核验范围、期限、独立性与只读发布前检查见 [来源核验](source-verification.md)。编辑通过、专业意见和来源查证都不直接发布。

| 表 | 关系与用途 |
| --- | --- |
| source_records | 来源 ID、最新修订和唯一的当前规范化网址 |
| source_versions | `(source_id, revision)` 不可变版本，含标题、机构、URL、录入账号和时间 |
| content_revisions | `(ingredient_id, revision)` 不可变草稿、摘要、基础 release、作者和时间 |
| revision_sources | 联结内容与来源的固定版本，保存原文定位和引用顺序，两端使用复合外键 |
| content_drafts | 条目当前正文版本、协作版本、作者和状态；指向 content_revisions |
| review_tasks | 指向提交修订/摘要，保存提交者、状态、独立审阅者、意见与时间 |
| workflow_events | 操作类型、对象、修订、操作者和时间，不复制正文 |

上述模型由 schema v3 在事务中增量引入，不替换旧表或删除账号/备注；当前 schema v8 另含专业、来源与发布历史。每次来源修订、草稿保存、提交、审阅决定均将状态/版本与事件在同一事务中提交。不可变历史表由触发器拒绝 UPDATE/DELETE。本编辑模块没有删除、恢复旧正文为当前或直接公开草稿的接口；复用历史正文需保存为新修订。固定快照的发布、撤回、历史回滚已接入独立 [发布 API](publication-api.md)，不能绕过其门禁。

## API 契约

下表路径均相对 `/api/v1/editorial`。所有读取也需账号会话，本地密钥模式返回 403。写入沿用 Cookie、可信 Origin 与 X-CSRF-Token；JSON 大小上限 32 KiB，保证合法中文正文与 10 个定位不被旧备注的 8 KiB 限制挡住。

| 方法与路径 | 正文/查询与结果 | 权限 |
| --- | --- | --- |
| GET `/sources` | `q/page/pageSize`，查询最新版本，每页最多 50 条 | 所有账号 |
| POST `/sources` | `{title,publisher,url}`，创建版本 1 | 管理员/编辑 |
| GET `/sources/:id` | 可带 `revision` 取得固定历史版本，不带则返回当前头 | 所有账号 |
| PUT `/sources/:id` | `{source:{title,publisher,url},expectedRevision}`，追加新版本 | 管理员/编辑 |
| GET `/ingredients/:id` | `{draft,revisions,tasks,contributorIds}`，最近 20 个正文修订与任务，以及完整参与者 ID | 所有账号 |
| GET `/ingredients/:id/revisions/:revision` | 精确取得历史修订及固定来源，即使它不在最近 20 条中 | 所有账号 |
| PUT `/ingredients/:id` | `{content,expectedLockVersion}`，新草稿用 0 | 管理员/草稿作者 |
| POST `/ingredients/:id/submit` | `{expectedLockVersion}`，返回草稿和绑定任务 | 管理员/草稿作者 |
| GET `/tasks` | `status=pending/accepted/returned` 与分页 | 所有账号 |
| GET `/tasks/:id` | 精确取得任务状态、修订/摘要和意见 | 所有账号 |
| POST `/tasks/:id/decision` | `{decision:'accept'或'return',comment,expectedLockVersion}` | 独立管理员/审阅者 |
| GET `/events` | 最近 50 条协作记录 | 所有账号 |

来源标题必填、最多 200 字；发布机构必填、最多 120 字；规范化 URL 最多 1000 字，只接受无账号密码的 HTTP/HTTPS。保存仅登记，`verificationState=pending` 固定，不允许请求体伪造已核验或公开状态。来源更新不改写草稿已引用的旧版本。

来源库、草稿来源选择器和待编辑条目查询失败时不显示上次结果，也不当作零条匹配；明确重试不会覆盖已打开的编辑输入。来源保存与重载使用同步进行中保护，重复表单事件不能重复提交。修复前证据、实际HTTP/SQL验证与边界见[来源查询恢复](source-lookup-recovery.md)。

`content` 精确字段：`ediblePart`（200）、`latinName`（200）、`educationText`（1600）、`safetyText`（1000）和 `sourceRefs`（最多 10 个）。每条引用精确为 `{id,revision,locator}`，定位必填且最多 400 字，同一来源不能重复引用，引用版本须真实存在。可保存未完成草稿；提交必须有教育说明、安全边界和至少一个来源。不允许提交审校状态、发布标志、用量、诊断字段或其他未知字段。没有针对自由文本的医学语义审核，故任何草稿均不得通过此流程公开。

错误沿用 400/401/403/404/409/413；409 包括来源/草稿冲突、已锁定提交、非法流转和完整性错误。编辑审阅通过响应始终 `professionalReviewState=pending`、`visibility=private`、`publicationEnabled=false`。这些固定字段不能作为未来发布授权。

## 本地演示步骤

1. 优先按 [独立本地演示](local-demo.md) 新建专用库并启动，不使用工作库。若采用 README 的常规工作库入口，已有账号库不要重复初始化。
2. 独立演示已准备管理员、编辑和审阅者三个随机密码账号。常规工作库则由管理员在“账号权限”另行创建协作账号，安全交付密码，不在截图中展示凭据。
3. 编辑登录 → 内容协作 → 来源登记，输入可追溯标题、机构和原始网址，保存私有待核验记录。
4. 内容修订 → 选择食材，填写教育说明、安全边界，引用登记来源固定版本并填写原文定位，保存后提交编辑审阅。
5. 审阅者在另一浏览器会话登录 → 编辑审阅任务，查看提交快照与出处，填写意见并退回。
6. 编辑重新加载草稿，查看退回意见，保存新修订并再次提交。
7. 独立审阅者确认编辑质量后选择“通过编辑审阅（不发布）”。检查它仍私有待专业审校，小程序目录未被覆盖。
8. 查看修订历史、来源版本与协作事件；刷新/重启服务后记录仍在。来源修改产生新版本，旧草稿继续引用原版本。

以上演示证明页面 → HTTP → 权限/状态机 → 事务/关系表 → 页面更新，不证明内容医学正确或可上线发布。测试账号和测试意见只存在独立测试库，不能当作真实专业审校证据。

## 管理端响应边界（2026-10-11）

草稿、来源登记/选择和编辑审阅现在通过 `web/api.ts` 的 `requestDecoded` 接收未知JSON，再由纯TS `shared/workflow-response.ts` 明确构造展示数据。前端类型不能证明服务器或中间链路返回了正确对象；这些检查也不替代服务端权限、事务、摘要验证或专业批准。

| 数据 | 读取检查与关联 |
| --- | --- |
| 固定来源 | 精确字段、HTTP/HTTPS且无网址凭据、私有待核验状态；固定读取核对ID和修订 |
| 草稿/正文修订 | 字段长度、唯一固定引用、已返回来源的ID/版本匹配、食材与指定修订一致、协作版本及私有状态 |
| 草稿详情 | 同一食材的修订/任务、历史唯一性、当前正文/来源/摘要与对应修订一致；当前作者须在完整贡献列表中 |
| 保存/提交/审阅响应 | 保存核对规范化后的本次输入与预期版本推进；提交绑定原正文和任务；审阅响应绑定任务正文及决定状态 |
| 分页列表 | 数量、页码/页大小、去重；审阅列表额外绑定查询状态，错误列表不解释成零条 |
| 来源核验 | 当前来源ID/固定修订/摘要、跨修订全局核验版本、最近20条连续记录与当前修订最新记录关联；测试记录不得显示为真人查证通过 |
| 来源核验保存 | 绑定本次规范化输入、操作者/账号版本与预期核验版本+1；未知回执保留输入并暂停提交，失败重读不解锁 |
| 发布前资料检查 | 所选食材、正文/摘要/基础版本、来源核验版本、缺失域/原因与齐备标志一致；始终私有且不启用发布 |
| 专业页账号/资格 | 账号明确投影、唯一身份/名称；资格历史含userId，即使为空也核对归属；最近20条连续修订，历史过期或账号版本失效不误删 |
| 专业详情/决定 | 空详情含ingredientId；当前草稿、两类最新意见及最近20条历史关联，允许最新意见在窗口外；写回绑定操作者/资格/协作版本/提交意见，并保持旧正文及历史不变 |
| 发布工作区/快照 | 所选食材、正文和固定来源/专业依据、删减资格投影、当前指针/批准/冻结批次、最近20条事件连续性；当前/指定旧快照可追加在最近20条之外 |
| 发布写回 | 快照、批准、发布/撤回/回滚、冻结/恢复分别解析，绑定提交输入、操作者、账号版本、预期版本推进、快照/批准版本和冻结批次；不共用错误的快照类型 |
| 账号管理/安全事件 | 创建绑定规范化意图及新身份；更新/重读绑定同一账号不可变身份、权限和版本；完整列表不能遗漏已知账号导致输入丢失。事件明确投影/动作、递减ID及50条窗口，允许序列间隙 |
| 工作台目录/统计 | 目录绑定请求页码、页大小、字面搜索及ID排序，自身总数与本页条数一致；统计精确字段、安全整数及有效日期，历史模式/发布标志不充当公开权限 |
| 备注审计/协作日志 | 分别最多20/50条，明确动作与对象、正修订和递减ID，允许序列间隙；协作来源事件只指向来源、正文事件只指向食材，不接受私有附加字段 |
| 备注详情/保存/清空 | 食材与备注归属一致；零修订只能为空文字/null时间，已写入允许清空但保留正修订和时间。保存绑定本次trim后输入与修订+1，重读禁止修订倒退/同版本替换及导入目录变更 |
| 认证配置/会话/登录/退出 | 配置明确模式、会话精确账号/CSRF/有效期限；登录绑定用户名，退出ok=true。未知写入须显式GET核对，失败不清空输入；不能接管不同身份或静默替换旧工作台凭据 |

正文修订的固定来源对象缺失时保留明确的缺口展示，不能把另一个来源或新版填进去；原有 `hasFixedSourceReferences` 仍禁止通过编辑审阅，允许退回补充。当前草稿与保存响应则不接受缺失的固定来源。客户端只核对摘要格式和关联，不重新计算密码学摘要，不把一致性当作事实正确或来源认证。

成功HTTP携带无效JSON/业务数据时，只读操作提示重新读取；写入提示无法确认提交结果，保留输入，不清除确认之外的状态、不显示保存成功、不自动重发。请求编号仅取校验后的响应头，解析器原始错误/损坏数据不回显。取消后即使传输仍返回成功JSON，也不解析或交付过期结果。

草稿保存/提交、编辑审阅、来源核验、专业资格/意见及发布管理额外使用同步写入门禁；传输失败/超时或损坏成功响应使操作进入待核对状态，停用保存、提交、审阅及辅助采用，不因修改输入或失败的重新读取解锁。人工确认重新加载且完整响应检查成功后才恢复操作。专业意见须同时成功核对所选固定内容和本人资格，不能仅一项成功就解锁。发布管理隐藏旧公开状态、批准和历史，明确未知结果不等于尚未保存或已经撤回。离开/会话变更取消客户端等待，不将取消解释成服务器撤销写入。来源保存仍保留已有同步提交保护；初次来源保存响应未知时可按标题/网址查找实际记录，不自动再次创建。

迁移覆盖来源登记、草稿及编辑审阅主链路、来源核验、发布前资料检查、专业资格/意见、发布管理、账号创建/权限更新与安全事件及各自食材选择器，以及工作台目录/统计/备注审计、协作日志和备注详情/保存/清空/重读、认证配置/登录/会话/退出；摘要采用时的来源/草稿复核也使用同一边界。部分AI配置、摘录/许可/额度仍有旧 `request<T>` 调用或未核对业务回执，不能称全部管理契约已运行时校验；后续逐条迁移，保持服务器独立执行授权。新模块不导入服务端或私有研究，不进入小程序。

备注编辑状态独立于目录批次：同步门禁防止同帧重复保存/清空，读写取消和回写绑定每次选项/会话拥有者，切换先确认未保存或未核对输入，旧响应不能覆盖新食材。保存失败保留输入和旧修订，暂停保存/清空；普通刷新、修改输入、取消重读或失败重读不能解锁。重读须人工确认替换输入，完整校验成功后才恢复手动操作，不自动补发。当前读取可包含其他请求的新修订，不能据此归因先前提交；若原请求稍后提交，乐观锁仍由服务端独立拒绝冲突。备注不进入专业批准或公开内容。
